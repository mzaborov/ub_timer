## Context

Мотивация и объём — в [proposal.md](proposal.md); требования — в [specs/org-situation-booklet/spec.md](specs/org-situation-booklet/spec.md). Ограничения, формирующие подход:

- Портал — чистый PHP без сборки; **composer в проекте нет**. Библиотеки кладут прямо в `portal/vendor/` (прецедент: `Parsedown.php` подключается в [materials.php](../../../portal/materials.php), JS — в `portal/vendor/*.min.js`).
- Деплой портала — по FTP ([scripts/deploy_portal.ps1](../../../scripts/deploy_portal.ps1)), с исключениями; shared-hosting Masterhost (лимиты памяти/времени).
- БД — MySQL через `mysqli` (глобальный `$db` в [bootstrap.php](../../../portal/inc/bootstrap.php)).
- Данные: `situations(code, num, duel_type, description, roles_json, is_published)`, `duels(event_id, sort_order, situation_id)`, `events(...)` (поля логотипа сейчас нет).

## Goals / Non-Goals

**Goals:**
- Серверная генерация PDF-буклета без внешних сервисов и без composer.
- Переиспользование существующего доступа к БД и структуры орг-страниц.
- Минимальная, безопасная дельта схемы (одно поле логотипа) и деплой в один шаг.

**Non-Goals:**
- Редактор буклета в UI, шаблонизация на стороне клиента, экспорт в DOCX/RTF.
- Хранение истории/версий сгенерированных буклетов.
- Пер-мероприятийная инструкция судьям (пока только общий текст).
- Изменения в таймере, судьях и протоколе.

## Decisions

### 1. PDF-библиотека: mPDF из self-contained релиза в `portal/vendor/`
Выгрузка PDF делается HTML→PDF движком. Кандидаты: **mPDF** (self-contained ZIP со своими зависимостями), dompdf (нужны composer-зависимости: `php-font-lib`, `php-svg-lib`, `sabberworm/php-css-parser` — несколько ручных папок), TCPDF (без composer, но слабый HTML/CSS).
**Выбор: mPDF** — самодостаточный релиз (кладётся как `portal/vendor/mpdf/`), лучшая поддержка UTF-8 (кириллица) и таблично-типографского HTML под наш буклет; согласуется с практикой «положить в vendor».
**Альтернатива:** dompdf — легче, но требует ручного вендоринга нескольких пакетов и хуже переносит CSS-разметку.
**Смягчение размера:** из релиза удаляются лишние шрифты (оставляем DejaVu Sans/Serif), примеры и тесты.

### 2. Генерация в поток, без временных файлов
Обработчик `org_booklet.php?action=booklet&event_id=…&scope=…&judge=…` строит HTML и вызывает mPDF `Output()` в режиме скачивания/просмотра с `Content-Type: application/pdf`. Временные файлы на диске не создаются.

### 3. Источник данных и порядок
Буклет собирается из тех же таблиц, что и остальной портал.
- Состав «мероприятие»: `SELECT DISTINCT situation_id FROM duels WHERE event_id=? AND situation_id IS NOT NULL ORDER BY sort_order` → порядок по слотам.
- Состав «все»: `SELECT … FROM situations WHERE is_published=1 ORDER BY num, code`.
- Группировка на секции — по `duel_type` в порядке «классика → экспресс → парный»; пустые секции не выводятся.
- Карточка: заголовок «Ситуация N (оригинальный num)», `description` как есть; блок «Роли и интересы» — из `roles_json` (без блока, если пуст). Разметка ролей (`<strong>`) сохраняется.

### 4. Логотип мероприятия: новое поле `events.logo_path` + `portal/uploads/events/`
Добавляется колонка `logo_path VARCHAR(512) NULL` (миграция `003_event_logo.sql`). Загрузка в карточке мероприятия пишет файл в `portal/uploads/events/<event_id>.<ext>` (png/jpg; ограничение типа и размера) и сохраняет относительный путь.
**Дефолты для «купала»/«новогоднее»:** два предустановленных логотипа кладутся в `portal/assets/`; при создании мероприятия этих типов `logo_path` инициализируется дефолтом, плюс разовый бэкфилл для существующих мероприятий. На обложке: если `logo_path` не задан — блок логотипа просто не выводится (не ломая генерацию).

### 5. Общая инструкция судьям — файл контента, рендер через Parsedown
Единый текст инструкции хранится как файл в репозитории (`portal/content/judge-instructions.md`) и рендерится уже вендоренным `Parsedown` (как в [materials.php](../../../portal/materials.php)). Отдельная страница буклета (page-break до/после ситуаций). Позже при необходимости переносится в БД без смены спеки.

### 6. Точка входа и доступ
Кнопка/секция «Буклет ситуаций» в карточке мероприятия в [org_events.php](../../../portal/inc/org_events.php); проверка, что текущий пользователь — организатор этого мероприятия (существующая логика доступа орг-страниц). Логика сборки — в новом `portal/inc/org_booklet.php`.

## Risks / Trade-offs

- [Лимиты памяти/времени shared-hosting на «все ситуации»] → ужать шрифты mPDF, поднять `memory_limit` локально в обработчике, проверить на полном банке; при необходимости — пагинировать/ограничить.
- [Отсутствие расширений PHP (mbstring/gd) на хостинге] → проверить наличие перед внедрением; mPDF требует `mbstring`; `gd` — для масштабирования изображений.
- [Размер vendor при FTP-деплое] → prune лишних шрифтов/примеров; включить vendor в деплой осознанно, а не исключением.
- [Качество кириллицы и логотипа] → проверить рендер PDF с русским текстом и png-логотипом; SVG-логотипы не поддерживать в v1.
- [Дубли ситуаций в сетке] → `DISTINCT` + порядок по первому слоту; в спецификации зафиксировано.

## Migration Plan

1. Миграция `003_event_logo.sql`: `ALTER TABLE events ADD COLUMN logo_path VARCHAR(512) NULL`.
2. Разовый бэкфилл `logo_path` для мероприятий типов «купала» и «новогоднее».
3. Вендоринг mPDF в `portal/vendor/mpdf/` + контент инструкции + дефолтные логотипы.
4. Коммит → деплой портала по FTP ([scripts/deploy_portal.ps1](../../../scripts/deploy_portal.ps1)).
5. Проверка: генерация двух вариантов по мероприятию с логотипом и без, с инструкцией и без.
6. Откат: удалить поле `logo_path` и файлы `portal/vendor/mpdf/` (код обработчика не вызывается без кнопки); данные ситуаций не меняются.
