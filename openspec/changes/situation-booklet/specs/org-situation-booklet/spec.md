## Purpose

Генерация серверного PDF-буклета ситуаций по мероприятию «Управленческих поединков»: печатная раздатка с текстами ситуаций из банка, с вариантами состава (все / только мероприятие) и наличием общей инструкции судьям, с обложкой, несущей логотип мероприятия.

## ADDED Requirements

### Requirement: Запуск генерации буклета организатором мероприятия

Организатор мероприятия SHALL иметь возможность запустить формирование буклета ситуаций из рабочего места организатора. Генерация MUST быть доступна только организатору этого мероприятия и MUST NOT быть доступна участникам и зрителям. По завершении система MUST отдавать готовый **PDF-файл** (скачивание или печать).

#### Scenario: Организатор формирует буклет
- **WHEN** организатор открывает карточку мероприятия и запускает формирование буклета
- **THEN** система формирует PDF-файл буклета и отдаёт его на скачивание

#### Scenario: Нет доступа у не-организатора
- **WHEN** буклет пытается сформировать пользователь, не являющийся организатором мероприятия
- **THEN** генерация недоступна и файл не формируется

### Requirement: Выбор состава ситуаций

Перед генерацией система SHALL предлагать выбор состава: «все ситуации из банка» или «только ситуации мероприятия». Вариант по умолчанию — «только ситуации мероприятия». Состав «все ситуации» MUST включать все опубликованные ситуации банка.

#### Scenario: Все ситуации банка
- **WHEN** выбран состав «все ситуации»
- **THEN** в буклет попадают все опубликованные ситуации банка

#### Scenario: Только ситуации мероприятия
- **WHEN** выбран состав «только ситуации мероприятия»
- **THEN** в буклет попадают только ситуации, назначенные слотам сетки этого мероприятия

### Requirement: Источник состава «только мероприятия»

Для состава «только ситуации мероприятия» система MUST брать уникальные ситуации, назначенные слотам сетки мероприятия. Ситуации без назначенной ситуации MUST NOT попадать в буклет. Порядок ситуаций в буклете SHALL соответствовать порядку слотов мероприятия.

#### Scenario: Уникальные ситуации из сетки
- **WHEN** несколько слотов мероприятия используют одну и ту же ситуацию
- **THEN** она попадает в буклет один раз

#### Scenario: Порядок по слотам
- **WHEN** формируется состав «только мероприятия»
- **THEN** ситуации выводятся в порядке их появления в слотах мероприятия

#### Scenario: Пустая сетка
- **WHEN** в сетке мероприятия нет ни одной назначенной ситуации
- **THEN** система сообщает, что ситуаций для буклета нет, и не формирует пустой файл

### Requirement: Общая инструкция для судей

Система SHALL поддерживать вариант буклета «с инструкцией для судей». Инструкция MUST быть общим методическим текстом, единым для мероприятия, и MUST размещаться в буклете на **отдельной странице** (до или после ситуаций). Вариант «без инструкции» MUST NOT включать эту страницу.

#### Scenario: Буклет с инструкцией
- **WHEN** выбран вариант «с инструкцией для судей»
- **THEN** в буклете присутствует отдельная страница с общей инструкцией судьям

#### Scenario: Буклет без инструкции
- **WHEN** выбран вариант «без инструкции»
- **THEN** страница с инструкцией в буклете отсутствует

### Requirement: Обложка и логотип мероприятия

Первая страница буклета SHALL содержать обложку с заголовком мероприятия и датой. Мероприятие SHALL иметь логотип, отображаемый на обложке. Логотип MUST задаваться в карточке мероприятия (загрузка файла организатором). Для мероприятий типов **«купала»** и **«новогоднее»** логотип SHALL быть проинициализирован значением по умолчанию.

#### Scenario: Обложка с логотипом
- **WHEN** формируется буклет мероприятия с заданным логотипом
- **THEN** обложка содержит заголовок, дату и логотип мероприятия

#### Scenario: Логотип по умолчанию для купалы и НГ
- **WHEN** создано мероприятие типа «купала» или «новогоднее»
- **THEN** у него заранее задан логотип по умолчанию

#### Scenario: Организатор загружает логотип
- **WHEN** организатор загружает файл логотипа в карточке мероприятия
- **THEN** логотип сохраняется и используется на обложке буклета

### Requirement: Структура буклета

Буклет SHALL группировать ситуации по типу поединка: секции «Классические», «Экспресс», «Парные» (секция выводится, если в неё попала хотя бы одна ситуация). Каждая карточка ситуации MUST содержать: заголовок с порядковым номером в буклете и оригинальным номером ситуации, текст ситуации и блок «Роли и интересы» (если он задан для ситуации).

#### Scenario: Группировка по типам
- **WHEN** в буклет попали ситуации разных типов
- **THEN** они выводятся в отдельных секциях по типу поединка

#### Scenario: Карточка ситуации
- **WHEN** выводится карточка ситуации
- **THEN** показаны номер (порядковый и оригинальный), текст ситуации и блок «Роли и интересы», если он задан

#### Scenario: Пустые роли
- **WHEN** у ситуации не задан блок «Роли и интересы»
- **THEN** карточка выводится без этого блока

### Requirement: Ограничения вывода

Буклет MUST быть представлен форматом PDF, пригодным для печати. Тексты ситуаций MUST выводиться как есть из банка (без редактирования данных). Генерация MUST NOT изменять ситуации, слоты и данные мероприятия.

#### Scenario: Только чтение
- **WHEN** формируется буклет
- **THEN** данные ситуаций, слотов и мероприятия остаются без изменений

#### Scenario: Кириллица и специальные символы
- **WHEN** в тексте ситуации есть кириллица и спецсимволы
- **THEN** они корректно отображаются в PDF-файле
