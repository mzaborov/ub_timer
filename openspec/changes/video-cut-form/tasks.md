## Факты реализации (2026-10-26)

- Раздел: `portal/?p=org&s=videocut` → [org_videocut.php](../../../portal/inc/org_videocut.php), [org-videocut.js](../../../portal/js/org-videocut.js), [org-videocut.css](../../../portal/css/org-videocut.css).
- Абсолютное время поединка берём из `protocol_events.payload_json.server_ts` (epoch ms). Отдельной колонки `server_ts` в схеме нет; `moment_sec` — секунды от старта поединка.
- Границы по протоколу: начало — последнее `раскрытиеСитуации` перед поединком (первое — автооткрытие после предыдущего решения, второе — после выбора ситуации); конец — `решениеСудей`. `завершение` не используется: оно наступает до обсуждения судей и даёт короткий фрагмент. При первом выборе файла старт записи автоматически калибруется по последнему решению и длительности: `lastDecisionMs − duration + tail`; вручную заданный старт не перетирается.
- Локальный файл читается браузером (`URL.createObjectURL`), на портал не загружается. Нарезка/публикация ждут локальный сервис.
- Навигация: кнопки ±1/5/15/30/60 с; «точка начала» сдвигает весь таймлайн под выбранный поединок (старт по левому полному кадру, `Math.floor(t*fps)/fps`, fps по умолчанию 25), кнопка «[ в точке» двигает только этот поединок. Сдвиг хранится в черновике и экспорте.
- В карточках поединков — превью первого и последнего кадра; кадры берутся с `±frameEps` от границ и обновляются при изменении границ, сдвига и fps.
- Стартовую папку браузерного `<input type="file">` задать нельзя (в Яндекс.Браузере нет File System Access API); в форме есть подсказка про `Документы\Zoom`, стартовую папку задаёт локальный сервис (2.4).
- Публикация ссылок: `POST action=org_vc_publish_video` (CSRF, проверка `duel_id`/`event_id`, upsert `videos` по `duel_id` + `video_type='Поединок'`).
