# Управленческие поединки - Часы
Этот проект представляет собой программу для управления временем в ходе управленческих поединков. 

посмотреть можно на https://timer.zaborov.ru

- Открыть локально: `index.html` в браузере (для загрузки .xlsx/.json может понадобиться локальный сервер из-за CORS).

## Функциональность
- Поддерживает классические поединки и экспресс:
  - считается количество раундов
  - ведется подсчет голосов судей
  - есть функционал пауз и протестов
- **Расписание** можно загрузить **из файла** (.xlsx/.json) или **из Google** (лист «состав онлайна» + банк ситуаций) — см. [ниже](#загрузка-расписания)
- во время поединка показывается текст ситуации, текущие роли и их интересы (для классики) или агрессивная вводная фраза (для экспрессов)
- **Слот «Случайная ситуация»** (`SituationNum` = `00` / `00Э`): кнопка-кубик рядом с выбором поединка — резолв из банка — см. [ниже](#случайная-ситуация-00--00э)
- **Секрет названия (Hidden):** необязательная колонка в файле расписания — размытие названия до клика — см. [ниже](#секрет-названия-колонка-hidden) (это **не** то же самое, что слот `00`/`00Э`)
- **Протокол → Google / Live:** меню «Протокол» — файл, снимок в сетку состава, очистка, автопуш — см. [ниже](#протокол--google-live)
- **Судья ФУБ** (`experience: "expert"`): пометка в «Участники и судьи» — приоритет автоназначения на «Отправляющие» / «Доверяющие» (см. [логику автоназначения](#логика-автоназначения-судей))

## Часы
- У каждого игрока — круговой индикатор (бублик) и поле с оставшимся временем. Запуск и остановка общих часов — кнопкой «Возобновить» / «Остановить часы».
- **Редактирование времени при остановленных часах:** когда часы остановлены и поединок идёт, можно задать время вручную: **двойной клик** по цифрам времени в центре бублика (по полю «4:25»). Откроется поле ввода. Формат: **М:СС** (например `4:30`, `0:05`) или **число секунд** (например `270`). Введённое значение ограничивается: больше 0 и не больше времени поединка из настроек (длительность раунда из файла). **Enter** или клик вне поля — применить; **Escape** — отмена без изменений.

## Звуки

**Включение и выключение**

В тулбаре есть переключатель звука (иконка динамика): чекбокс с иконкой «громко» / «выкл». По умолчанию звук включён. При выключении все звуки отключаются, текущие воспроизведения останавливаются (тиканье, гонг, гудок, барабанная дробь, аплодисменты, музыка жребия).

**Когда какие звуки играют**

- **Тиканье** (`clock_ticking.mp3`) — когда осталось мало времени: во время таймера судей (последние секунды) и во время таймера паузы. Останавливается при остановке часов, таймера судей или паузы.
- **Гонг** (`Gong.mp3`) — время текущего игрока закончилось (0), у второго ещё есть (переход хода); также при окончании времени паузы (0 сек).
- **Гудок** (`Gudok.mp3`) — время закончилось у обоих игроков (автоматическое завершение поединка).
- **Барабанная дробь** (`Drum_roll.mp3`) — по нажатию кнопки с иконкой барабана в форме завершения поединка (равный счёт, ждём оценку последнего судьи); также при кручении **кубика случайной ситуации** (`00`/`00Э`), если звук не выключен.
- **Аплодисменты** (`applause.mp3`) — по нажатию кнопки с иконкой аплодисментов; также по умолчанию при нажатии «Завершить поединок» (завершить без звука — **Shift+клик** по кнопке; подсказка при наведении — см. [форму завершения](#форма-завершения-поединка)).
- **Музыка жребия (интро)** — при нажатии «Жребий» (ЛКМ по кнопке с иконкой кубика) воспроизводится трек из `assets/Sound/intro/` (список в `list.json`, при деплое обновляется автоматически). По умолчанию — случайный трек; конкретный трек задаётся через ПКМ по той же кнопке (меню с названиями композиций). Повторное нажатие на кнопку жребия останавливает музыку и досрочно выбирает игрока. Под кнопкой во время жеребьёвки показывается таймер обратного отсчёта до конца трека (исчезает по окончании или при досрочной остановке).

**Где лежат файлы**

- `assets/Sound/` — гонг, гудок, тиканье, барабанная дробь, аплодисменты.
- `assets/Sound/intro/` — треки для жребия; список в `assets/Sound/intro/list.json`.

## Загрузка расписания

Меню **«Выберите файл» → «Загрузить расписание»** (подменю вправо):

| Пункт | Действие |
|-------|----------|
| **из Google последний** | Берёт крайнюю (правую) встречу с листа «состав онлайна», join с банком ситуаций |
| **из файла** | Локальный `.xlsx` / `.json` (как раньше) |
| **из Google выбрать** | Модалка со списком встреч (новые сверху), кнопка «Загрузить» / «Обновить список» |

**Источник Google:** published CSV листа состава (`gid=1172864695`, строки сетки встреч 1–21, рост вправо) + банк ситуаций (тот же spreadsheet). Тексты ситуаций подтягиваются по номеру (`SituationNum` / `110`, `00Э`…). Кэш встреч — `sessionStorage`. После загрузки из Google для протокола запоминается контекст встречи (имя + колонки) и **включается Live-запись** (см. [Протокол → Google](#протокол--google-live)).

Реализация: `js/schedule.js` (`loadScheduleFromGoogleLatest`, `openGoogleSchedulePicker`, `buildDuelsListFromGoogleMeeting_`). План: [docs/Архив/расписание_из_google.plan.md](docs/Архив/расписание_из_google.plan.md).

## Формат файла расписания (Excel / JSON)

Поддерживаются файлы **.xlsx** (первая строка — заголовки столбцов, данные со второй) и **.json** (корень — массив объектов поединков). Тот же набор полей собирается при загрузке из Google.

| Поле | Описание |
|------|----------|
| **DuelNum** | Номер поединка в списке |
| **Player1** | Имя первого игрока |
| **Second 1** | Секундант первого игрока (рекомендуемые названия колонок в Excel: **Second 1**, **Second 2**; допускаются также Cornerman 1/2, Секундант 1/2) |
| **Player2** | Имя второго игрока |
| **Second 2** | Секундант второго игрока |
| **SituationNum** | Номер ситуации |
| **SituationName** | Название ситуации |
| **RefereeQty** | Количество судей для поединка. Допустимые значения: **9, 7 или 5**. При загрузке и в runtime число **нормализуется** к ближайшему из {5, 7, 9}; при равной дистанции — **вверх** (например 6→7, 8→9, 4→5). Экспресс всегда **5** судей. |
| **Type** | Тип поединка: `Классика`, `Парный` или `Экспресс` |
| **DuelMinutesLength** | Длительность раунда в минутах: 5, 4 или 1 |
| **SituationDescription** | Текст ситуации в HTML-разметке; возможные роли выделяются тегом `<strong>`, например `<strong>ИТ Директор</strong>` |
| **SituationRoles** | Роли: для **Классика** и **Парный** — массив `{ "Role": "роль", "Goals": "интересы" }`; для **Экспресс** — два объекта `{ "Role": "роль", "Phrase": "агрессивная фраза" }`. В Excel — строка с JSON в ячейке |
| **Hidden** | *(необязательно)* См. раздел [«Секрет названия (колонка Hidden)»](#секрет-названия-колонка-hidden). |

**Отображение имён в UI:** для Классики — `Игрок (Секундант)`; для Парного — `Игрок + Секундант` (логика часов как у Классики); для Экспресса — только игрок. В таблице «Расписание» имена по одному в ячейке (классика — отдельные строки «Игрок» и «Секундант»; экспресс — только «Игрок», без секундантов; парный — объединённая ячейка «игрок + секундант» на сторону, подпись строк «Секундант/игрок»).

## Случайная ситуация 00 / 00Э

Отдельная механика от колонки **Hidden** (blur). В сетке состава / расписании слот с номером **`00`** (классика) или **`00Э`** (экспресс) показывается как «Случайная ситуация…».

1. Выбираете такой поединок в выпадашке.
2. Рядом с кнопкой названия появляется **кнопка-кубик** (не путать с центральным жребием хода между игроками).
3. Клик: анимация + `Drum_roll` (если звук вкл.) → из **банка ситуаций** выбирается случайная ситуация того же типа, которой ещё нет среди `SituationNum` текущего онлайна.
4. В поединок подставляются номер, название, описание, роли и т.п.; в списке слот становится с обычным номером.
5. Пока поединок не начат (`idle`, не завершён) — можно **перебросить** (флаг `wasRandomSlot`). При перебросе номер текущего слота снова может выпасть.

При включённой Live-записи после резолва/переброса номер ситуации уходит в Google (событие 2).

Реализация: `js/schedule.js` (`rollRandomSituation`, `updateRandomSituationDiceButton`). План: [docs/Архив/случайный_поединок.plan.md](docs/Архив/случайный_поединок.plan.md).

## Секрет названия (колонка Hidden)

Формат онлайна, где игроки **не знают тему заранее**: ведущий **сам** выбирает поединок из списка, но название ситуации скрыто до момента выбора. Автоматический рандомайзер по банку **здесь не используется** (для рандома — слот `00`/`00Э` выше).

**Пример расписания:** `Таблицы для онлайнов/Онлайн я-ИТ-ы №26.xlsx` — колонка **Hidden**, значения `1` или пустая ячейка.

### Колонка в Excel / JSON

| Значение | Поведение |
|----------|-----------|
| `1`, `да`, `true`, `yes`, `+`, `x` | Название ситуации **размыто** (CSS blur) в UI до выбора поединка |
| Пустая ячейка | Обычное отображение |
| Колонки нет (старые файлы) | Без изменений, всё видно сразу |

Допустимые заголовки колонки: **Hidden**, HideSituationName, HideSituation, «Скрыть название», «Случайная ситуация». После загрузки в объекте поединка хранится флаг `hideSituationName` (boolean).

### Где скрывается название

| Место | Что размыто |
|-------|-------------|
| Выпадашка **«Выберите поединок»** | Часть строки `№N :: <название>` |
| Вкладка **«Расписание»** (форма «Участники и судьи») | Вторая строка заголовка колонки под «Поединок N» |

**Раскрытие:** один раз выбрали поединок в выпадашке — его название становится читаемым и в списке, и в таблице «Расписание»; остальные строки с `Hidden=1` остаются размытыми.

### Где название **не** скрывается

- Кнопка «Выберите поединок» после выбора, заголовок `#Duel_Num`, текст ситуации на основном экране — как раньше (текст ситуации по-прежнему прячется чекбоксом «газета» в тулбаре).
- Имена игроков, секундантов и судей в таблице «Расписание».

### Сохранение в протоколе

Список уже раскрытых поединков (`revealedSituationIndices`) сохраняется в **localStorage** и на листе **«Состояние сессии»** при «Сохранить статус онлайна»; восстанавливается при «Восстановить последний онлайн» и «Загрузить статус онлайна».

**Реализация:** `js/schedule.js` (`parseTruthyCell`, `renderDuelChooser`, `renderJudgesLayoutTab`), стиль `.situation-name-blurred` в `css/timer.css`.

## Форма «Участники и судьи»

Открывается из меню **«Выберите файл»** → **«Участники и судьи»** (пункт активен после загрузки расписания). Две вкладки: **Участники** и **Расписание**.

### Вкладка «Участники»

- Таблица: **№**, **ФИО**, **Статус** (активен), **Особенности назначения**, **Судит**, **Игр**, **Сек.** (сколько раз секундирует).
- **Особенности назначения** — радиокнопки: без пометки (—), **новичок**, **опытный**, **судья ФУБ**, **орг**. Влияют на автоназначение: «судья ФУБ» (приглашённые профсудьи) ставятся в первую очередь — предпочтительно в «Отправляющие», затем «Доверяющие», при избытке — и в «Нанимающиеся»; лимита судейств нет. «Орг» заполняют только в последнюю очередь в оставшиеся слоты; новичков предпочтительно ставят в «Нанимающиеся», опытных — в «Доверяющие»/«Отправляющие».
- **Судит** / **Игр** / **Сек.** — сколько раз человек уже судил, играл или секундировал (считается по расписанию и назначениям).
- Над таблицей: поле **«ФИО нового участника»** и кнопка **«Добавить участника»** (**Enter** в поле — то же действие, что по кнопке).

### Вкладка «Расписание»

- Таблица: строки — роли (Игрок, Секундант, Нанимающиеся 1…, Отправляющие 1…, Доверяющие 1…); колонки — поединки. В заголовке колонки: «Поединок N» и название ситуации; при **Hidden=1** название **размыто** до выбора поединка в выпадашке (см. [выше](#секрет-названия-колонка-hidden)). Набор строк зависит от типа расписания:
  - **Классика** — игрок, секундант (×2), затем судейские строки по числу судей (5/7/9).
  - **Экспресс** (все поединки экспресс) — две строки «Игрок» и пять «Отправляющие 1…5» (секундантов нет).
  - **Смешанное** (классика/парный и экспресс в одной сессии) — всегда **пять строк «Отправляющие 1…5»** плюс «Нанимающиеся» и «Доверяющие» по `RefereeQty`. Одна и та же строка «Отправляющие N» в разных колонках может означать **разный слот** `j` (см. [ниже](#смешанное-расписание-слоты-экспресса)). В колонках экспресса «Нанимающиеся» и «Доверяющие» серые; активны все пять «Отправляющих»; игроки — в двух строках «Игрок» (без секундантов). В колонках классики и парного — как обычно.
- **Редактирование** — только **незавершённые** поединки (серые колонки — только просмотр).
- **Двойной клик** по ячейке — выбор участника из списка с поиском. Доступно для:
  - **Классика:** игрок, секундант, судья;
  - **Экспресс:** игрок, судья (Отправляющие 1…5);
  - **Парный:** судья; игрок/секундант — в одной объединённой ячейке (отдельно секунданта пока не выбрать).
  В списке нет тех, кто уже занят в этом поединке в другой роли; текущий человек в ячейке в списке есть (можно оставить или заменить).
- **Одинарный клик** по ячейке **текущего** поединка — подтвердить назначение (зелёная подсветка); на других поединках одинарный клик ничего не меняет.
- **ПКМ** по ячейке — контекстное меню:
  - **Очистить** — снять назначение с ячейки.
  - **Поменять местами** — режим обмена: подсвечивается ячейка-источник и доступные цели (любая редактируемая ячейка в **незавершённом** поединке, где уже есть человек; после обмена никто не участвует дважды в одном поединке). Клик по доступной ячейке выполняет обмен; **Escape** — отмена.
  - **Не может на этот поединок** — только для **судейских** слотов: очистить слот, записать человека в исключения на этот поединок (под капотом), подобрать одну замену по приоритетам автоназначения; ручное назначение этого человека в этот поединок по-прежнему разрешено. Исключения на поединок **не сохраняются** при восстановлении из localStorage или из файла статуса (только на текущую сессию). При подборе замены участники с пометкой «орг» не предлагаются.
  - **Отключился со встречи** — только для **судейских** слотов: пометить человека неактивным, подобрать замену на текущий поединок, пересчитать все будущие поединки.
- **Кнопки:**
  - **«Автоназначение судей»** — заполняет судей по всем текущим и будущим поединкам (прошедшие не трогает). **Ctrl+клик** по кнопке — то же плюс скачивание файла с логом назначений.
  - В заголовке колонки поединка (только **незавершённые**, не экспресс) — выпадающее меню:
    - **«Назначить судей на этот поединок»** — автоназначение только для этой колонки;
    - **«5 судей» / «7 судей» / «9 судей»** — явно задать число судей для поединка (классика и парный). Меняет поле `RefereeQty`, перерисовывает таблицу (лишние судейские строки становятся серыми) и **синхронизирует форму голосования**, если она открыта для этого поединка.

#### Число судей и форма голосования

- На форме «Поединок завершён» число **кнопок судей** (5, 7 или 9) берётся из **`RefereeQty` текущего поединка**, а не из числа уже назначенных фамилий в таблице. Если в файле указано 7, а назначено 5 человек, на форме будет **7 кнопок** (в том числе пустые слоты с подписью «Судья N»).
- Чтобы уменьшить число кнопок до 5, выберите **«5 судей»** в меню заголовка колонки **до или во время** голосования (иконка судьи в футере формы → вкладка «Расписание»).
- При смене 5/7/9 во время голосования уже проставленные голоса **сохраняются по слотам** (j0…j8), где слот остаётся в составе.
- При закрытии модалки «Участники и судьи» во время голосования форма **подтягивает актуальный** `RefereeQty` из таблицы.
- При завершении раунда (`stop_duel`) форма сразу строится по `RefereeQty` поединка (без рассинхрона с предыдущим поединком).
- Из формы голосования **нельзя** переключить 5/7/9 — только через таблицу «Расписание» (кнопка с иконкой судьи в футере модалки завершения).

#### Смешанное расписание: слоты экспресса

В **смешанной** сессии строки таблицы общие, а **физические слоты** `j0…j8` зависят от типа поединка в колонке (`getJudgeSlotsForDuel`, `getLayoutSlotKey` в `js/schedule.js`):

| Строка таблицы | Классика (7 судей) | Экспресс (5 судей) |
|----------------|-------------------|---------------------|
| Отправляющие 1 | j2 | j3 |
| Отправляющие 2 | j3 | j4 |
| Отправляющие 3 | j4 | j5 |
| Отправляющие 4 | *(серая)* | j6 |
| Отправляющие 5 | *(серая)* | j7 |

Активность ячейки определяется **типом поединка**, а не подписью строки (строки «Доверяющие» в колонке экспресса тоже могут содержать судей-отправляющих, если слот j5/j6 используется в классике соседней колонки — в экспрессе для них показываются «Отправляющие 4–5»).

**Автоназначение:** основной алгоритм идёт по коллегиям классики; в конце — отдельный проход **`fillRemainingExpressJudgeSlots`**: все пустые слоты экспресс-поединков (`j3…j7`) заполняются через `findBestCandidateForSlot`.

**Форма голосования:** имена на кнопках подставляются по порядку видимых кнопок и списку слотов `getJudgeSlotsForDuel` (не по индексу кнопки в массиве `judges[]`); для экспресса пустые коллегии «Нанимающиеся» и «Доверяющие» **скрываются**, блок «Отправляющие» — по центру.

### Логика автоназначения судей

При нажатии **«Автоназначение судей»** алгоритм идёт **по людям** (внутри каждого шага — по участникам, а не по слотам), с учётом **опытности**, **соседства в коллегии** и **разнообразия коллегий**. ФИО в алгоритме не участвуют (при равенстве критериев — сравнение по id).

**Коллегии:** «Нанимающиеся» (hiring), «Отправляющие» (negotiators), «Доверяющие» (owners). **Соседство** — один и тот же поединок и одна коллегия (кто уже назначен в эту коллегию в этом поединке). Алгоритм минимизирует повторное соседство (не ставить одних и тех же людей в одну коллегию в разных поединках подряд).

**Порядок опытности** во всех шагах 1–3 (первая итерация): **новички → опытные → none** (внутри группы — по возрастанию числа судейств). Судьи ФУБ и орги в шаги 1–3 не входят.

#### Проход 0 — судьи ФУБ (`experience: "expert"`)

Перед шагами 1–3: отдельный проход **без лимита** слотов на человека. Порядок коллегий: **Отправляющие → Доверяющие → Нанимающиеся**. Внутри слота — минимум мягкого соседства (для коллегий из 1 слота соседство не учитывается) и минимум уже назначенных судейств. Игры/секундирование не запрещены, но обычно эксперты только судят; в своём поединке (игрок/секундант) не назначаются.

#### Первая итерация (раунд 1)

**Шаг 1 — только судьи** (не играли, не секундируют, не орг, не судья ФУБ):

- **Новички:** сначала до **2 слотов в «Нанимающиеся»** в максимально ранних поединках (слоты j0, j1), с минимизацией соседства и разнообразием; при 5+ поединках — **3-й слот** в другой коллегии (Отправляющие/Доверяющие), тоже с учётом соседства.
- **Опытные:** только коллегии 2 и 3 (Отправляющие, Доверяющие); распределение по ранним поединкам, минимизация соседства и разнообразие коллегий.
- **None:** любые коллегии, ранние поединки, минимизация соседства и разнообразие.

**Шаг 2 — секунданты** (уже секундируют, не играют):

- Порядок: новички → опытные → none. **Новички-секунданты:** до 2 слотов сначала в «Нанимающиеся» (если есть свободные), затем остальные слоты — любые коллегии. Соседство и разнообразие учитываются.

**Шаг 3 — игроки** (уже играли):

- Порядок: новички → опытные → none. **Новички-игроки:** до 2 слотов сначала в «Нанимающиеся», затем остальные — любые коллегии. Соседство и разнообразие учитываются.

**Сортировка слотов при выборе места для человека:** сначала минимизируется **соседство** (cost по уже назначенным в этой коллегии в этом поединке), затем **ранний поединок**, затем **разнообразие коллегий** (предпочтение коллегии, где человек судил меньше раз). После каждого назначения список свободных слотов пересобирается и пересортируется (чтобы соседство учитывалось после предыдущего назначения).

**Лимиты слотов на человека** (за один запуск): при 5+ поединках — шаг 1: 3, шаг 2: 2, шаг 3: 2; при меньшем числе поединков — 2, 1, 1. Орги и судьи ФУБ не участвуют в шагах 1–3 (судьи ФУБ — в проходе 0).

#### Вторая и последующие итерации (раунды 2, 3, …)

Свободные слоты заполняются без учёта опытности и соседства: среди подходящих по шагу выбирается участник с **минимальным числом судейств** (и границы шага соблюдаются). Лимит на человека увеличивается на 1 с каждым раундом. Судьи ФУБ и орги не участвуют.

#### Орги

В конце отдельным проходом оставшиеся пустые слоты заполняются участниками с пометкой «орг» (по минимуму судейств).

#### Экспресс и смешанное расписание

После прохода оргов выполняется **`fillRemainingExpressJudgeSlots`**: для каждого незавершённого экспресс-поединка проверяются слоты `j3…j7` из `getJudgeSlotsForDuel`; пустые заполняются по тем же приоритетам, что и ручная замена (`findBestCandidateForSlot`) — судьи ФУБ предпочтительны для слотов «Отправляющие».

#### Ограничения

- **«Нанимающиеся»:** в первую очередь только новички; если новичков нет — слот может заполниться опытным или none.
- Неактивные участники исключаются. Игроки и секунданты конкретного поединка не назначаются судьями в этом же поединке.

#### Отладка

**Ctrl+клик** по кнопке «Автоназначение судей»: скачивается текстовый файл с порядком назначений (имя вида `autofill-log-YYYYMMDDHHMMSS.txt`).

## Форма завершения поединка
- **Число кнопок судей:** **5, 7 или 9** для классики и парного (по `RefereeQty`); для экспресса — **5** (только «Отправляющие на переговоры»). Смена числа — в таблице «Расписание» (см. выше).
- **Раскладка коллегий:**
  - **Классика / парный** — три колонки («Нанимающиеся», «Отправляющие», «Доверяющие»); группы кнопок **по центру** колонки; кнопки в одну линию, высота ~2.35rem, `max-width` ~8.5rem.
  - **Экспресс** — видна только колонка «Отправляющие» (5 кнопок по центру модалки); блоки «Нанимающиеся» и «Доверяющие» скрыты (`updateRefereeCategoryColumns` в `js/referees.js`).
- **Кнопки с именами судей:** на кнопке — **полное ФИО** (шрифт 0.85em при длинном имени); обрезка с многоточием; **полное имя** — во всплывающей подсказке. Порядок имён соответствует назначениям в таблице «Расписание» (маппинг через `getJudgeSlotsForDuel`).
- **Иконка судьи** в футере — открывает «Участники и судьи» (вкладка «Расписание») для правки состава и числа судей без закрытия формы голосования.
- **Звуки:** две кнопки-иконки — барабанная дробь (равный счёт, ждём оценку последнего судьи) и аплодисменты (все судьи проголосовали, судья объявляет результат). Иконки — Font Awesome в папке `fontawesome/`.
- **Завершить поединок:** по умолчанию при нажатии воспроизводятся аплодисменты; завершить без звука — **Shift+клик** по кнопке. При наведении или фокусе с клавиатуры — всплывающая подсказка **под** кнопкой (приглушённый серый стиль, мелкий шрифт): «По умолчанию — с аплодисментами. Shift+клик — без звука» (`bootstrap.Tooltip`, `container: "body"`, в `js/init.js`; класс `.tooltip-finish-duel` в `css/timer.css`).

## Протокол онлайна

Меню **«Выберите файл» → «Протокол»** (активно после загрузки расписания):

| Пункт | Действие |
|-------|----------|
| **Сохранить в Google** | Ручной снимок текущей встречи в сетку состава (только если расписание загружено **из Google**) |
| **Сохранить в файл** | Excel: «Протокол» + «Раунды» (имя вида **«Протокол &lt;имя расписания&gt;.xlsx»**) |
| **Очистить Google** | Откат ячеек встречи к слепку на момент загрузки расписания из Google |
| **Live-запись: вкл\|выкл** | Автопуш в Google по событиям (см. [ниже](#протокол--google-live)); при загрузке из Google по умолчанию **вкл** |

- Длительности раундов считаются по **игровому времени** (таймеры/бублики), без учёта пауз и протестов. Время сохраняется при **переходе хода** и при **завершении поединка**. Поддерживается **произвольное число раундов**; в Excel-протоколе выводятся паузы, протесты и роли по раундам (для классики).
- После подтверждения завершения поединка выбор автоматически переключается на **следующий поединок** в списке (если он есть).

### Протокол → Google (Live)

Клиент: [`js/live-protocol.js`](js/live-protocol.js). Сервер: GAS Web App (`doPost`), лист состава `gid=1172864695` (та же сетка, откуда читается расписание). Исходник GAS и деплой: [`scripts/google-apps-script/LIVE_PROTOCOL_SOURCE.md`](scripts/google-apps-script/LIVE_PROTOCOL_SOURCE.md). Ключ — Script Property / `localStorage` (`LIVE_PROTOCOL_KEY`), не коммитить боевой секрет.

**Пишем:** ситуация, участники/секунданты, судьи, «Начинал», голоса судей.  
**Не пишем:** победитель и счёт (формулы таблицы), видео.

При **Live-запись: вкл** автопуш по событиям:

| # | Событие | Что уходит в сетку |
|---|---------|-------------------|
| 1 | Изменение состава | Судьи (+ игроки/секунданты при смене) |
| 2 | Резолв / переброс `00`/`00Э` | Ячейка «Ситуация» |
| 3 | Жребий хода | Только «Начинал» = Команда 1 / Команда 2 |
| 4 | Голос судьи | «Судья N Голос» = `1`\|`2` (каждый клик) |

Стороны в Google — фиксированные **Команда 1 / Команда 2**; после жребия UI может поменять местами Player1/Player2 — клиент маппит голоса и «Начинал» на команды сетки.

Это **не** offline-импорт в лист «протоколы игр» ([docs/protocol/](docs/protocol/)). План: [docs/Архив/live_протокол_google.plan.md](docs/Архив/live_протокол_google.plan.md).

### Логика восстановления (для пользователей и разработчиков)

Ниже подробно описано, как сохраняется и восстанавливается состояние онлайна: при обновлении страницы, при работе с файлом статуса и при случайном закрытии формы судей.

#### Откуда берётся состояние

- **localStorage** (ключ `ub-timer-online-state`): сюда автоматически записывается состояние при выборе поединка, старте/остановке поединка, смене игрока, выборе роли, во время тика таймера в раунде и при голосовании/смене судьи. В объекте хранятся: имя файла расписания, список поединков (с результатами и флагами `hideSituationName`), **revealedSituationIndices** (какие поединки с Hidden уже «открыли» в выпадашке), **фаза** (`idle` / `round` / `judges`), выбранный поединок, время на часах обоих игроков, номер раунда, длительности прошедших раундов, роли по раундам, паузы и протесты, при фазе судей — голоса судей и активный судья, число судей (9/7/5) и т.д.
- **Фазы:**
  - **idle** — поединок не идёт, форма судей не открыта; сохраняется только выбранный поединок.
  - **round** — идёт раунд; сохраняются время, раунд, активный игрок, длительности, роли, паузы/протесты.
  - **judges** — открыта форма голосования судей; дополнительно сохраняются голоса и активный судья.

#### Баннер «Восстановить последний онлайн?»

- Появляется при загрузке/обновлении страницы, если в localStorage есть сохранённые данные и при этом либо есть «реальные» данные протокола (победители, длительности раундов, голоса), либо фаза была `round` или `judges` (активная сессия).
- **«Да»** — восстанавливаются имя файла расписания и список поединков, отображается список; восстанавливается выбранный поединок (ситуация, имена, роли из расписания). Если фаза была **round**: на экране восстанавливаются часы (остановлены), номер раунда, время у каждого игрока, длительности раундов, текущий игрок, выбранные роли для текущего раунда; кнопка «Завершить поединок» активна. Если фаза была **judges**: то же состояние раунда плюс открывается модалка формы судей с восстановленным количеством судей (9/7/5), голосами и активным судьёй.
- **«Нет»** — баннер скрывается; восстановление не выполняется (расписание и список поединков можно загрузить заново из файла).
- **«Очистить»** — данные в localStorage удаляются, баннер скрывается.

#### Кнопки на баннере

- **«Сохранить статус онлайна»** — скачивается один файл .xlsx с тремя вкладками: «Протокол» (игроки, победитель, голоса судей по поединкам), «Раунды» (длительности, роли, паузы, протесты по раундам), «Состояние сессии» (текущая фаза, поединок, время, раунд, судьи и т.д. в виде «ключ — значение»). Если в момент сохранения открыта форма судей, голоса текущего поединка в «Протокол» подставляются из текущего состояния (localStorage), а не только из уже завершённых поединков.

#### Загрузка статуса онлайна (выпадающее меню «Выберите файл»)

- Пункт **«Загрузить статус онлайна»** в меню под кнопкой «Выберите файл» по умолчанию **неактивен**. Он становится активным только **после загрузки файла расписания** (.xlsx или .json). Так обеспечивается соответствие: статус загружается поверх уже открытого расписания.
- После выбора файла .xlsx приложение:
  1. **Не пересоздаёт** список поединков с нуля: из листа «Протокол» по индексу колонок обновляются только поля уже загруженных поединков (игроки, победитель, голоса судей).
  2. Из листа «Раунды» заполняются длительности раундов, роли, паузы и протесты по каждому поединку.
  3. Если есть лист «Состояние сессии», по нему восстанавливается этап: фаза, выбранный поединок, время на часах, раунд, голоса судей, число судей и т.д. — по той же логике, что и при «Восстановить последний онлайн» (см. выше).
  4. Состояние записывается в localStorage, баннер восстановления скрывается.

#### Форма голосования судей: кнопка «Вернуть голосование»

- Кнопка **«Вернуть голосование»** (под кнопкой «Начать поединок») показывается в фазе **idle**, если только что был завершён поединок: вы нажали «Завершить поединок» в форме судей, модалка закрылась и выбор переключился на следующий поединок — в этот момент кнопка появляется.
- По нажатию открывается форма голосования **не для текущего (подсвеченного) поединка, а для предыдущего** — того, который только что завершили. Восстанавливаются количество судей (9/7/5) и все проставленные голоса из сохранённого результата.
- Кнопка скрывается, когда вы **начинаете следующий поединок** («Начать поединок» для следующего в списке).

#### Краткая памятка для пользователей

| Ситуация | Действие |
|----------|----------|
| Обновили страницу / открыли снова | Если появился баннер — «Восстановить последний онлайн?» → **Да** для восстановления этапа (раунд или судьи). |
| Хотите перенести/бэкап онлайна | **Сохранить статус онлайна** → сохранить .xlsx. Потом на другом устройстве/браузере: загрузить **расписание**, затем **Загрузить статус онлайна** и выбрать этот .xlsx. |
| Завершили поединок, хотите снова посмотреть голосование | В фазе idle под кнопкой «Начать поединок» нажать **«Вернуть голосование»** — откроется форма судей для **предыдущего** поединка. |
| Загрузить статус без расписания | Сначала загрузить файл расписания («Загрузить расписание»), затем в меню станет доступно «Загрузить статус онлайна». |

**Структура протокола (Excel):** при **«Сохранить в файл»** (меню Протокол) и при **«Сохранить статус онлайна»** в файл входят листы «Протокол» и «Раунды»; при «Сохранить статус онлайна» добавляется третий лист — «Состояние сессии» (см. раздел «Логика восстановления» выше).

**Лист «Протокол»** — общие данные по поединкам (столбцы = поединки):

| Столбец A (метка) | Столбцы B, C, D… (Поединок 1, 2, 3…) |
|-------------------|----------------------------------------|
| Игрок 1 | Имя первого игрока |
| Игрок 2 | Имя второго игрока |
| Секундант 1 | Секундант первого игрока |
| Секундант 2 | Секундант второго игрока |
| Тип поединка | Классика / Экспресс |
| Победитель | Имя победителя (или пусто) |
| Судья 1 … Судья N | ФИО судьи (из формы раскладки судей) |
| Судья 1 Голос … Судья N Голос | Голос судьи: 1 или 2 (N = max количества судей, 9/7/5) |

**Лист «Раунды»** — по одной строке на раунд поединка:

| Поединок | Раунд | Длительность | Игрок 1 Роль | Игрок 2 Роль | Время паузы | Протесты |
|----------|-------|--------------|---------------|--------------|-------------|----------|
| 1 | 1 | 2:30 | … | … | 1:45 | |
| 1 | 2 | 3:00 | … | … | | 0:50, 1:20 |

Роли — только для классики; в колонке «Протесты» — список времён через запятую (протестов может быть несколько в раунде).

## Банк ситуаций (Google Sheets)

Банк ситуаций хранится в Google-таблице (лист **Ситуации**). Для ub-timer в расписании используются колонки **SituationDescription** (HTML с `<strong>` для ролей) и **SituationRoles** (JSON).

### Просмотр (этап 1 — готово)

Отдельная страница [situations-bank.html](situations-bank.html) (прод: `https://timer.zaborov.ru/situations-bank.html`):

- mobile-first, вёрстка в стиле AppSheet (оранжевая шапка, список → карточка);
- ссылка из таймера: **«Выберите файл» → «Банк ситуаций»**;
- данные из published CSV; кэш `sessionStorage` (1 ч);
- фильтр пустых и служебных строк; свайп между ситуациями; кнопка «Поделиться»;
- HTML/JSON при наличии, иначе plain text; для **Экспресс** блок ролей в карточке скрыт.

Файлы: `situations-bank.html`, `css/situations-bank.css`, `js/situations-bank.js`.

**Локально:** не открывайте `situations-bank.html` через `file://` (будет «Failed to fetch»). Из корня репо: `python -m http.server 8765` → [http://localhost:8765/situations-bank.html](http://localhost:8765/situations-bank.html).

### Автогенерация (этап 2 — готово)

Google Apps Script + LLM (OpenRouter или DashScope):

- шаблон: [`scripts/google-apps-script/enrich-situations.gs`](scripts/google-apps-script/enrich-situations.gs) (локально, в `.gitignore`);
- инструкция: [`scripts/google-apps-script/README.md`](scripts/google-apps-script/README.md);
- версия скрипта — в заголовке `.gs` (сейчас **1.2.5**).

Меню **«Банк ситуаций»** в таблице:

| Пункт | Назначение |
|-------|------------|
| Сгенерировать для пустых / выделенных | LLM заполняет пустые `SituationDescription` / `SituationRoles` |
| Исправить экспрессы | Чинит JSON экспрессов **без токенов** |
| Проверить API-ключ | Тест OpenRouter / DashScope |

**Промпты по типу:** Классика/Парный — `{Role, Goals}`; Экспресс — `[{"Role","Phrase"},{"Role"}]` (Phrase только у первой роли).

Уже заполненные ячейки **не перезаписываются**. Лог — лист `_enrich_log`.

**Настройка LLM** (Script Properties таблицы): `QWEN_API_KEY`, `LLM_PROVIDER` (`openrouter` | `dashscope`), опционально `QWEN_MODEL`.
