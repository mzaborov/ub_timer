# Формат `protocols-batch` v1

Машиночитаемый пакет бумажных протоколов поединков. Один файл — один турнир (или одна сессия).

См. также: [обзор pipeline](pipeline.md), [логика импорта в таблицу](import.md).

## Версия

| Поле | Значение |
|------|----------|
| `format` | `"protocols-batch"` |
| `version` | `1` |

## Структура файла

```json
{
  "format": "protocols-batch",
  "version": 1,
  "meta": {
    "tournament": "Купала 2026",
    "eventDate": "2026-06-27",
    "source": "pdf:имя-файла.pdf",
    "notes": ""
  },
  "duels": [ … ]
}
```

### `meta`

| Поле | Обяз. | Описание |
|------|-------|----------|
| `tournament` | да | Название турнира — должно совпадать с началом заголовка **row 2** колонки в таблице |
| `eventDate` | нет | Первая/основная дата турнира; при нескольких днях точная дата — в `matchHints.eventDate` каждого поединка |
| `source` | нет | Откуда взяты данные (`pdf:…`, `ub-timer`, …) |
| `notes` | нет | Произвольные пометки к файлу |

### `duels[]`

| Поле | Обяз. | Описание |
|------|-------|----------|
| `situationNum` | да | Номер ситуации из **расписания** (для матчинга колонки) |
| `situationLabel` | нет | Полный текст ситуации; при импорте может перезаписать row 8 |
| `roles.player1` | да | ФИО **Игрока №1** (после жеребьёвки на бланке) |
| `roles.second1` | да | ФИО секунданта у Игрока №1 |
| `roles.player2` | да | ФИО **Игрока №2** |
| `roles.second2` | да | ФИО секунданта у Игрока №2 |
| `judges[]` | да | `{ "name": "Фамилия Имя", "vote": 1 \| 2 }` — голос за Игрока №1 или №2 |
| `teams` | нет | Только при экспорте из ub-timer; с бумаги **не заполняется** |
| `matchHints.eventDate` | да* | Дата поединка (`YYYY-MM-DD`) — для матчинга заголовка row 2 (`{tournament} DD.MM.YYYY`). *Обязательно, если турнир на несколько дней |
| `matchHints.situationNumOnPaper` | нет | Номер на бланке, если отличается от `situationNum` (OCR, опечатка) |
| `matchHints.expectedColumn` | нет | Буква колонки (`GS`…), если матчинг иначе неоднозначен |
| `notes` | нет | Расхождения бланк/расписание — для предпросмотра импорта |

### Что не кладём в JSON с бумаги

Поля ниже **не** входят в файл с PDF — их вычисляет импорт ([`import.md`](import.md)):

- `teams` — пары «Команда 1 / Команда 2» для строк 9–12 таблицы
- `startedByTeam` / «Начинал» — строка 3 таблицы

## Имена

Формат **«Фамилия Имя»** — обязателен для формул и сводных в Google-таблице.

При подготовке JSON из PDF однословные фамилии дополняются в два шага:

1. **Ростер турнира** — если человек уже есть в этом JSON в другой роли (игрок / секундант / судья), берём его ФИО.
2. **Индекс прошлых протоколов** — лист «протоколы игр» в Google-таблице.

Скрипт: [`scripts/enrich-protocol-names.py`](../../scripts/enrich-protocol-names.py). Уже указанное «Фамилия Имя» не подменяется, если имя совпадает с индексом.

Синонимы с бланка (нормализация при дополнении):

| На бланке | Канон |
|-----------|--------|
| `Чистохин`, `Чистяхин` | `Чистюхин` |
| `Кунилова` | `Куликова` (если Куликова уже в ростере турнира) |

## Минимальный пример одного поединка

```json
{
  "situationNum": 11,
  "roles": {
    "player1": "Мельник Максим",
    "second1": "Елисеева Юлия",
    "player2": "Буковский Александр",
    "second2": "Заборов Михаил"
  },
  "judges": [
    { "name": "Комиссаров Арсений", "vote": 1 },
    { "name": "Куликова Ия", "vote": 2 }
  ],
  "matchHints": {
    "eventDate": "2026-06-27"
  }
}
```
