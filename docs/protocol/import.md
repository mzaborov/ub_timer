# Импорт протоколов в Google-таблицу

Загрузка файлов [`protocols-batch` v1](batch-format.md) на лист **«протоколы игр»** через Apps Script `import-protocols.gs`.

См. также: [обзор pipeline](pipeline.md), [установка GAS](../../scripts/google-apps-script/README.md#импорт-протоколов-поединков).

## Таблица

[я-ИТ-ы Управленческие поединки](https://docs.google.com/spreadsheets/d/1-qUmFGvuG2SOvueNUWr55zTZyFEXFFqiWTz8m-OVHZg/edit) — лист `протоколы игр`.

## Глоссарий: Команда vs Игрок

| Термин | Где | Смысл |
|--------|-----|-------|
| **Команда 1 / Команда 2** | Google-таблица, rows 9–12 | Пара «участник + секундант» в **турнирном слоте**. Бумажный протокол про команды **не знает**. |
| **Игрок №1 / Игрок №2** | Бумага, ub-timer, голоса судей (rows 23–31) | Роли в ситуации **после жеребьёвки** (`dice()` в [`js/core.js`](../../js/core.js)). |
| **Голос `1` / `2`** | JSON `judges[].vote` | За **Игрока №1** или **Игрока №2** (как таблички судей), **не** за Команда 1/2. |
| **Начинал** | row 3 таблицы | Какая **Команда** (слот) начинала. **Не в JSON** — вычисляет GAS. |

### Пример

- Команда 1: Трофимова + Заборов (rows 9–10)
- Команда 2: Щедрин + Ганичкин (rows 11–12)
- Жеребьёвка: Трофимова = **Игрок №1** → **Начинал = Команда 1**
- Если бы Игроком №1 стал Щедрин → **Начинал = Команда 2**

## Какие строки пишет импорт

| Строки | Содержимое | Примечание |
|--------|------------|------------|
| 3 | «Начинал» | Вычисляется из `roles` + раскладки команд |
| 8 | Ситуация | Из `situationLabel` или по номеру; может отличаться от плана |
| 9–12 | Команда 1 / Команда 2 | Участник + секундант по слотам |
| 13–21 | Судьи | Имена (до 9) |
| 22–30 | Голоса судей | `1`/`2` из JSON |
| 4–6 | Счёт, победитель | **Формулы — не трогаем** |

**Протокол — источник истины** для фактического состава и голосов. План в таблице используется для поиска колонки и ориентации слотов «Команда 1».

## Матчинг колонки

Заголовок колонки в таблице — **row 2**, формат: `{tournament} DD.MM.YYYY` (например, `Купала 2026 27.06.2026`).

Для каждого поединка из JSON:

1. Собрать ожидаемый заголовок: `meta.tournament` + дата из `matchHints.eventDate` (или `meta.eventDate`, если поединок один день).
2. Найти колонку с таким заголовком в row 2.
3. Уточнить по `situationNum` и/или участникам из плана (rows 9, 11).
4. При неоднозначности — `matchHints.expectedColumn`.

## Вывод `teams` и «Начинал»

JSON с бумаги содержит только `roles`. GAS читает **план** (row 9 колонки — кто в слоте Команда 1) и склеивает:

```
planTeam1 = row 9 до перезаписи

если samePerson(roles.player1, planTeam1):
  team1 ← { roles.player1, roles.second1 }
  team2 ← { roles.player2, roles.second2 }
иначе:
  team1 ← { roles.player2, roles.second2 }
  team2 ← { roles.player1, roles.second1 }

если roles.player1 ∈ team1 → row 3 = "Команда 1"
если roles.player1 ∈ team2 → row 3 = "Команда 2"
```

`samePerson` — нормализация «Фамилия Имя» по индексу имён из таблицы.

## Порядок работы

1. Подготовить JSON ([`batch-format.md`](batch-format.md), при необходимости `enrich-protocol-names.py`).
2. Вставить JSON в лист `_protocol_import`, ячейка **A1**.
3. Меню **«Протоколы игр»** → **Предпросмотр** — diff план vs протокол, предупреждения из `notes`.
4. **Выполнить импорт** — запись в колонки турнира.
5. Проверить формулы в rows 4–6 и сводные.

### Раскладка судей (v1.1.0)

В блоке из 9 строк судьи **центрируются** по числу в JSON:

| Судей | Имена (13–21) | Голоса (22–30) |
|-------|---------------|----------------|
| 9 | 13–21 | 22–30 |
| 7 | 14–20 | 23–29 |
| 5 | 15–19 | 24–28 |

Строки **1–2** не трогаем. **Эталон оформления** — колонка слева от самой левой в JSON-пакете (для Купалы обычно **GR**), не «сосед слева» у каждой колонки. Переопределение: Script Property `PROTOCOL_FORMAT_REF_COLUMN=GR`.

Лог операций — лист `_protocol_import_log` (создаётся скриптом).

## Нормализация имён при импорте

GAS сопоставляет ФИО из JSON с индексом имён на листе «протоколы игр» (те же правила, что при подготовке JSON). Несовпадения попадают в предпросмотр.
