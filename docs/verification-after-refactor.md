# Быстрая проверка после рефакторинга (разбиение по файлам)

Код не меняется — только группировка по файлам. Риски: неверный порядок `<script>`, отсутствующий файл или обращение к переменной/функции до загрузки модуля, где она объявлена.

## 1. Перед проверкой

- Убедиться, что в `index.html` все скрипты подключены в порядке из плана разбиения: `state.js` → `core.js` → `referees.js` → `schedule.js` → `toolbar-sound.js` → `protocol.js` → `init.js`, и у всех один и тот же `?v=N` (чтобы не подмешалась старая версия из кэша).
- Открыть DevTools (F12) → вкладка **Console**. Оставить открытой на время проверки.

## 2. Консоль при загрузке страницы

- Обновить страницу (Ctrl+F5 для сброса кэша при необходимости).
- В консоли не должно быть:
  - ошибок загрузки скриптов (404, сетевые ошибки);
  - `ReferenceError: ... is not defined` (значит что-то вызывается до загрузки файла с объявлением).
- Если есть — сразу видно, какой модуль или порядок скриптов виноват.

## 3. Один сквозной сценарий (дымовая проверка)

Один проход по основному сценарию затрагивает все вынесенные модули и подтверждает, что «ничего не сломало»:


| Шаг | Действие                                                                                                                                         | Что проверяется                                                         |
| --- | ------------------------------------------------------------------------------------------------------------------------------------------------ | ----------------------------------------------------------------------- |
| 1   | Загрузить расписание (кнопка загрузки xlsx, выбрать файл)                                                                                        | schedule.js, state, core (инициализация списка)                         |
| 2   | Выбрать поединок из списка                                                                                                                       | schedule.js (duelChoosed), core (отображение)                           |
| 3   | Нажать «Старт» поединка, затем «Старт» часов                                                                                                     | core.js (start_duel, start_timer)                                       |
| 4   | Переключить игрока (кнопка смены хода)                                                                                                           | core.js (changePlayer)                                                  |
| 5   | Пауза / снятие паузы                                                                                                                             | core.js (pause)                                                         |
| 6   | Остановить часы, завершить поединок (кнопка завершения)                                                                                          | core.js, toolbar-sound.js (finishDuelAndClose)                          |
| 6a  | В модалке — навести на «Завершить поединок»: тултип под кнопкой; обычный клик — с аплодисментами (если звук вкл.), **Shift+клик** — без звука | index.html, init.js (`bootstrap.Tooltip`), toolbar-sound.js             |
| 7   | В модалке завершения — голосование судей (выбрать победителя, таймер судей при необходимости)                                                    | referees.js                                                             |
| 8   | Закрыть модалку, открыть «Участники и судьи», добавить участника (**Enter** в поле ФИО или кнопка «Добавить участника»)                          | schedule.js (participants, duelAssignments)                             |
| 9   | Вернуться, снова открыть приложение — при наличии сохранённого состояния нажать «Восстановить» по баннеру или проверить, что баннер показывается | protocol.js (localStorage, баннер)                                      |
| 10  | Скачать протокол (кнопка экспорта/скачивания)                                                                                                    | protocol.js (buildProtocolAndDownload), schedule (getPersonName и т.д.) |


Если все шаги проходят без ошибок в консоли и интерфейс ведёт себя как до рефакторинга — группировка по файлам не сломала приложение.

## 4. Что можно не проверить при первой итерации

- Жребий (dice) и интро-треки — можно отложить, если нужно ещё быстрее.
- Импорт «Статус онлайна» из xlsx — достаточно проверить экспорт (шаг 10) и восстановление из localStorage/баннера.
- Двойной клик по таймеру для ручного ввода времени — edge case, после успешного сквозного сценария обычно достаточно.

## 5. Итог

- **Быстро:** загрузка страницы + консоль без ошибок + один проход «загрузить → выбрать поединок → старт → смена хода → пауза → стоп → завершение → судьи → участники → восстановление/экспорт» (порядка 5–10 минут).
- **Код не меняется** — только группировка по файлам, поэтому полный регресс-тест не обязателен; достаточно убедиться, что скрипты загружаются в правильном порядке и один сквозной сценарий выполняется без ошибок в консоли и с ожидаемым поведением UI.
