# 07. Генерация пар из заявок — бизнес-правила

**Статус:** черновик бизнес-правил (логика кнопки «Сгенерировать пары из заявок»).
**Дата:** 2026-10-13.
**Где в продукте:** рабочее место орги / мероприятие → карточка «Слоты», кнопка `#org-gen-pairs` ([org_events.php](../../portal/inc/org_events.php)). Сейчас — заглушка «Пока не умеем — скоро».
**Связанные документы:** [05_доменная_модель.md](05_доменная_модель.md), [памятка_орг_онлайн.md](памятка_орг_онлайн.md).

## Термины

- **Цель стрима** — 3 игры участника. Воронка: `без игр → сыграл 1 → сыграл 2 → сыграл 3` (см. `org_funnel_stage`). Достиг цели — `профи`/`наставник` (3+ игр). _(подтверждено 2026-10-13)_
- **Группа A** — участники, которые **не достигли цели стрима** (менее 3 игр): те, кого в первую очередь ведём по воронке. _(подтверждено 2026-10-13)_
- **Группа B** — участники, которые **достигли цели стрима** (3+ игр). _(подтверждено 2026-10-13)_
- **Новичок** — никогда не игравший (0 игр).

## Правила

### 1. Приоритет — у Группы A (не достигли цели стрима)

1.1. Приоритет у тех, кто **выше по воронке**: важнее предложить игру тому, кто ни разу не играл, чем тому, кто играл 2 раза. (Сначала `без игр`, затем `сыграл 1`, затем `сыграл 2`.)

1.2. **Без «перескоков»** между ступенями воронки. Тем, кто **не судил**, предлагать играть **последними внутри Группы A**. _(подтверждено 2026-10-13)_
Трактовка: внутри Группы A приоритет на игру — по воронке, но не судивших **опускаем в конец очереди на игру** (сначала пусть судят).

### 2. Жёсткое правило: два новичка — не друг против друга

Никогда не ставим двух новичков (у которых 0 игр) в одну пару. Они ещё не знают технологию — получится «месиво», а не поединок. Нормально ставить напротив участника из Группы A кого-то из Группы B (опытного в соперники новичку).

### 3. Разнообразие соперников (очень стараемся)

Стараемся не повторять пары. Если повтор и неизбежен — только те пары, которые играли **давно**.

### 4. Близкие по силе соперники (стараемся)

Подбирать соперников, близких по силе. **Метрика силы — Elo** (см. раздел «Метрика силы»). _(решено 2026-10-13)_

### 5. Приоритет для Группы B (достигли цели стрима)

Приоритет тем, кто **давно не играл**, плюс **разнообразие** пар, плюс **соответствие по силе** (по Elo).

## Метрика силы: Elo

_(решено 2026-10-13; выборочный тест на дампе 19.08.2026, 114 активных участников с играми.)_

- **Что считаем:** Elo по истории поединков (хронологически), как в шахматах.
- **Параметры по умолчанию:** старт `1500`, `K = 32`.
- **Исход поединка:** по большинству голосов судей (`судьи.голос` = `1`/`2`).
- **Стороны:** `классика` — 1×1 (`игрок1` vs `игрок2`); `парный` — 2×2, секунданты (`секундантИлиВторойИгрок`) считаются **игроками**; `экспресс` — 1×1 без секундантов.
- **Рейтинг стороны:** среднее Elo игроков стороны; обновляем каждого игрока стороны на его дельту.
- **Фолбэк:** при `< 3` играх Elo ещё не набрал вес — используем карьеру/группу силы как прокси.
- **Активность ≠ сила:** проверено — при равном числе игр Elo расходится на 200+ пунктов (напр. 17 игр → Elo 1429 vs 11 игр → Elo 1654). Кумулятивные баллы и число игр силу не отражают, поэтому отклонены.
- **Винрейт отклонён** как основная метрика: на 1–2 играх — шум.
- **Бухгольц отклонён:** тай-брейкер турнира, не общая сила.
- **Где считать:** на портале (PHP), из истории `duels` + голосов судей; кэшировать, пересчитывать при импорте нового протокола. Параметры (K, старт, порог фолбэка) — тюнингуемые.

Правило 2 (новичок × новичок) — **жёсткое вето**, независимо от Elo. Разнообразие пар (правило 3) учитывается отдельным весом, не через Elo.

## Реализация (решено 2026-10-13)

- **Кнопка** генерирует пары и **сразу сохраняет**; повторное нажатие даёт другой вариант.
- **Объём генерации:** только **игроки** (`p1`/`p2`) слотов типов **классика** и **экспресс**. Слоты **парного** и **секунданты** — вручную; генератор их не трогает. Парный — прецедентов нет, всегда руками.
- **Типы поединков** задаёт орг по слотам (`duels.duel_type`); генератор тип не меняет, только подбирает людей под него.
- **Квота** на человека: базово 1 поединок, при нехватке мест растёт до 2.
- **Ситуации** участники выбирают сами — генератор их не проставляет.
- **Секунданты** не подбираются; если секунданта выбрали **не из заявок**, он **автоматически добавляется** в заявку мероприятия.
- **Модель заявки — две части:**
  - **пожелания участника** (мягкие): роли (играть/судить/секундировать), тип поединка (как сейчас, одиночный: любой/классика/экспресс/парный), комментарий;
  - **пометки орга** (жёсткие, видны только оргу): **«не играть»** и **«запрещённые типы»**.
- **Приоритезация:** желание судить — слабый фактор (ср. п.1.2 «сначала пусть судят»).
- **Elo:** кэш в таблице `person_elo(person_id, elo, games, updated_at)`; расчёт в PHP при импорте протокола + разовый бэкфилл; фолбэк на карьеру при <3 играх; старт 1500, K=32. **Парный считается каждому участнику стороны** (игрок + второй игрок) как в классике: опорный рейтинг стороны — максимальный Elo её участников, дельта персонально каждому.

## Связь с доменом (якоря в коде)

- Воронка/цель: `org_funnel_stage()` — ступени `без игр / посудил / сыграл 1 / сыграл 2 / профи / наставник`.
- Карьера участника: `org_people_career()` — `games`, `judged`, `seconded`, даты последней игры/судейства/секундантства.
- Заявки: `org_event_regs()` — `play`, `judge`, `second`, `duel_type_pref`.
- Эвристика «кого звать и по какой ступени»: `org_reg_heat()`, `org_play_recs()`.
- Круг A (ядро): константа `COMMUNITY_A_CIRCLE` (`'A (Ядро)'`).
- Слоты/поединки: `org_slots_save()` (`duel_type`, `p1/p2`, `s1/s2`, `situation_id`). В `парном` секунданты (`s1/s2`) сами играют; в `экспрессе` секундантов нет.
- Образец алгоритма-аналога: автоназначение судей — `runJudgesAutofill()` (многопроходный жадный, баланс нагрузки, квоты с растущим лимитом, разнообразие троек).
