## 1. Роль и цель

Загрузить данные из существующих Google Sheets (и связанных артефактов репо), нормализовать их под **уже согласованный** канон домена и положить в репозиторий проверяемый слепок. Критерий: из слепка **воспроизводятся отчёты Google**. Публичный портал, PHP/MySQL на хостинге, редактирование — **не** этот шаг (шаг 3 = MySQL + просмотр, без витрины-заглушки). Цель шага 2: инвентарь + маппинг + скрипт выгрузки + JSON-дамп + сверка с отчётами.

## 4. Что сделать на шаге 2

Конкретный scope (сначала обсудить с пользователем, потом код):

1. **Инвентарь источников** — список листов/gid/диапазонов и локальных JSON; что публично читается CSV/gviz, что только через API. Зафиксировать в коротком md рядом с дампом.
2. **Маппинг лист → сущность** — таблица колонка/строка Google → атрибут канона. Дыры (нет источника) — **вопросы**, не новые классы и не пропуски молча.
3. **Скрипт выгрузки** — Python (как существующие), доступы из `.env` / `secrets.env` (SID, при необходимости OAuth). Не хардкодить секреты. Переиспользовать идеи `enrich-protocol-names.py` / gviz / CSV, не тащить SID в git как единственный путь.
4. **Нормализация под канон:**
   - ФИО → «Фамилия Имя»; синонимы как в `enrich-protocol-names.py`; жёсткого UNIQUE(ФИО) нет — коллизии в отчёт, решать вручную.
   - Типы: `классика` / `экспресс` / `парный` (один enum у ситуации и поединка).
   - Коллегии: три значения; в дамп — все судьи из сетки (ФИО и/или голос), и для экспресса, и для классики (не резать экспресс до «только Отправляющие»: таймер пишет 5 судей в строки 3–7). Пустой слот формы **не** запись `Судья`; `количествоСудей` = COUNT записей.
   - **`00` / `00Э` не создавать как Ситуация.** Слот в сетке → `Поединок.режимПодготовки = случайный`, ситуация 0..1 до события `расчетСитуации`.
   - Колонка Hidden / `скрытыйДоНачала` ≠ случайный слот (`hidden-ne-random`).
   - «Команда 1/2», `started_by` / «Начинал» — не поля домена; после жребия расставить актуальные `игрок1`/`игрок2` (+ слоты секундант/2-й игрок); факт жребия — событие протокола, если оно вообще есть в источнике.
   - Экспресс: `секундантИлиВторойИгрокNId` строго NULL; длительность 1; парный — 5; классика — 4 или 5.
   - Роли орга: закрытый `РольОрганизатора`; несколько ролей = несколько записей; UNIQUE(мероприятие, человек, роль).
   - Заявки: уникальность **внутри мероприятия** (email, иначе ФИО); не глобально по ФИО.
   - Круги: `степеньВовлечения` — строка (ЧС_A1, Функционер ФУБ, …), не ярлык новичок/опытный.
5. **Куда класть результат** — подтверждено: каталог [`05_данные/`](05_данные/) (инвентарь: [`sources.md`](05_данные/sources.md)):
   - JSON-слепок по классам yaml (люди, круги, мероприятия, поединки, судьи, ситуации, …);
   - без SQL seed;
   - `mapping.md` + `verify-report.md` (счётчики, коллизии ФИО, слоты 00/00Э, пустые коллегии, дыры источников).
   Не заливать в прод-MySQL на этом шаге.

## 5. Правила работы с пользователем (обязательно)

- Отвечать **по-русски**.
- **Сначала обсудить, дождаться подтверждения, потом писать код.** Не начинать скрипт выгрузки в том же ходе, что предложение.
- Доступы только из `.env` / `secrets.env`. Секреты не коммитить (`secrets.env`, oauth json, токены, боевой `LIVE_PROTOCOL_KEY`).
- После значимых вех — строка в корневой `History.log`: `YYYY-MM-DD HH:MM (+03:00)- …` (сам, без просьбы подтвердить текст).
- **Не коммитить**, пока пользователь явно не попросит.
- **Не трогать** раскладку `05_схема_БД.drawio` / SVG без нужды.
- Домен **согласован** — не улучшать схему, только маппинг. Дыры маппинга — вопросы пользователю, не молчаливые новые сущности и не новые инварианты.
- Кириллица в терминале: `chcp 65001` / `PYTHONIOENCODING=utf-8` (правило репо).
