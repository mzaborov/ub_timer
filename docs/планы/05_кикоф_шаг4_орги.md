## 1. Роль и цель

После входа как организатор (уже есть кнопка «Режим организатора» + пароль) человек должен попасть в **рабочее место орги**, а не остаться на публичном дашборде участников.

Цель шага 4 по плану 05: **редактирование** канона в MySQL без Google Sheets как источника истины. Четыре модуля:

1. люди;
2. ситуации;
3. мероприятия (в т.ч. Zoom и время 11:00–13:30);
4. материалы.

Публичный UX участников **не переделывать** (уже на проде). Орг-UI — отдельные экраны/навигация при `$_SESSION['org']`.

## 4. Что уже есть (вход в режим организатора)

Вход **уже сделан**, рабочего места **нет**.

1. Человек выбирает себя («Кто вы?») → cookie `ub_me` + сессия.

## 5. Четыре модуля

Сначала обсудить с пользователем оболочку (куда ведёт орги после пароля) и порядок модулей. Код — после подтверждения.

### 5.1. Работа с людьми

**Что орги делают:** список / поиск / карточка; создать, править, погасить (`is_active`); контакты (email, telegram), заметки. Не флаги новичок/опытный/орг — вовлечённость через `Круг` / `ЧленствоВКруге`.

**Уже есть:**

- таблица `people` + дамп [`05_данные/люди.json`](05_данные/люди.json) (~252);
- на портале `portal_people_list` — только `{id, name}` для autocomplete «Кто вы?»;
- «Моя статистика» и строка рейтинга — не карточка справочника.

**Нет:** экран справочника, карточка человека (ФИО, контакты, участия в поединках/мероприятиях), любой write API. В дампе email/telegram почти пустые — колонки есть, данных мало. Жёсткого UNIQUE(ФИО) нет: коллизии показывать, не схлопывать молча.

### 5.2. Работа с ситуациями

**Что орги делают:** список / поиск / карточка; создать и править код, тип (классика / экспресс / парный), описание, роли, `опубликована`. Подпись = конкатенация код+номер, не хранимое поле. Строки `00` / «случайная» — не записи банка.

**Уже есть:**

- таблица `situations` + дамп;
- публичный **GET** [`portal/api/situations.php`](../../portal/api/situations.php) (PHP 8.3, CORS на таймер);
- банк `situations-bank.html` читает этот API (не Google CSV);
- блок «Играли» на карточке — из `js/situation-plays.json` (сборка `scripts/build_situation_plays.py`), не live-запрос.

**Нет:** POST/PATCH для орги, UI редактирования, смена `is_published`. Публичный GET не закрывать и не ломать банк. Писать ситуации через Google / GAS на этом шаге **не надо**.

### 5.3. Работа с мероприятиями

**Что орги делают:** список / поиск / карточка; создать и править название, тип, статус, даты, **время начала/окончания**, **ссылку Zoom**, ярлык, арбитра. Онлайн по умолчанию **11:00–13:30 МСК**. В ICS и на портале для участников — короткий редирект `/z/{id}` (`portal/z.php` + rewrite в `.htaccess`), сырой Zoom только в БД.

**Уже есть:**

- таблица `events`: `starts_on`/`ends_on`, `starts_at`/`ends_at`, `zoom_url`, статус домена;
- календарь, «Ближайшее», заявка, ICS (`calendar.php`), редирект Zoom;
- шаблонные slug `online_10_20`…`online_10_24` скрыты с витрин (`portal_template_online10_slugs`).

**Нет:** орг-форма Zoom/времени (уже в плане 05 как долг шага 4); отдельная **карточка мероприятия** (публичная тоже не сделана — только виджет результатов на главной); CRUD мероприятия; сетка пар / состав поединков как редактор (памятка: «назначает пары» — кандидат, не первый ход).

Первый ход модуля — карточка + Zoom + часы + мета. Сетка поединков — отдельно, после подтверждения.

### 5.4. Работа с материалами

**Что орги делают:** список групп и ссылок; добавить / править / спрятать / поменять порядок. Участники по-прежнему видят read-only список.

**Уже есть:** захардкоженные ссылки в `portal/index.php` (Google Docs/Slides/Drive, Яндекс.Диск, YouTube, Xmind). Группы: «О поединках», «Как судить», «Как готовиться».

**Нет:** таблицы, API, UI. В каноне класса «Материал» нет — **не плодить доменный класс**. Варианты хранения (обсудить до кода): простая таблица вне UML (план §5 уже допускает `materials` вне модели) или JSON в репо/БД. Google Sheets как источник истины не использовать. Сами файлы остаются на Google/Яндексе — в системе только заголовок, группа, URL, порядок, флаг «показывать».

- люди — список, поиск, карточка, создание/правка;
