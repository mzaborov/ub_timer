### Решения по домену (зафиксировано)

- **Человек** — без `телефон`, без флагов опыта (`новичок` / `опытный`) и без глобального `орг`; вовлечённость — через **Круг** / **ЧленствоВКруге**.
- **Круг** — именованное сообщество (напр. «Я-ИТ_ы», «ФУБ»); **ЧленствоВКруге** связывает человека с кругом (`степеньВовлечения : String`).
- **Арбитр** — ассоциация `Человек "0..1" -- "0..*" Мероприятие : арбитр` (не отдельная роль-наследник; без дублирующих `арбитрId` / `арбитрФИО` на классе).
- **УчастиеВОрганизацииМероприятия** и **Наблюдатель** — отдельные сущности (`Мероприятие *--` многие); без общего абстрактного «УчастиеВМероприятии».
- **РегистрацияНаМероприятие** — заявки «хочу играть/судить/…»; не смешивать с оргами/наблюдателями.
- **«Команда 1/2» / номер команды** — артефакт Google; в модели нет (`команда`, `started_by_team`, слоты team1/team2 как турнирный якорь).
- **Состав поединка** — на `Поединок` только актуальный состав как `*Id` (`игрок1Id`, `секундантИлиВторойИгрок1Id`, `игрок2Id`, `секундантИлиВторойИгрок2Id`); без ФИО и без пар план/факт. Слоты `секундантИлиВторойИгрокNId`: классика — секунданты; парный — вторые игроки сторон (секундантов нет); экспресс — оба пустые. История изменений (в т.ч. бывший план/факт) — `ЖурналИзмененияПоединка` (`Поединок *--` 0..*). Иерархии `УчастиеВПоединке` / `ИгрокКоманды` / `Секундант` нет.
- **Жеребьёвка** — отдельного поля «кто начинал» (`ктоНачинал` / `started_by` / `СлотИгрока`) нет: после жеребьёвки актуальные `игрок1`/`игрок2` (и слоты секундант/2-й игрок) расставляются в данных поединка (при необходимости меняются местами); результат фиксируется **событием протокола** (`ТипСобытияПротокола`: жеребьёвка).
- **Судья** — отдельная сущность (`Поединок *--` многие): `idУчастника` (связь с `Человек`), коллегия, `голос` (опционально, за кого; не закрытый справочник); без индекса слота, без `отображаемоеИмя` и без `статусНазначения` (история — в журнале поединка). Число слотов 5/7/9 — `Поединок.количествоСудей`, не поле на судье.
- **Победитель / счёт** — не сущность и не атрибуты `Поединок`; отчёт/вычисление по `Судья.голос` (при необходимости — по событиям протокола).
- **Протокол** — только `СобытиеПротокола` (`Поединок *--` 0..*); отдельного `ПротоколПоединка` / `duel_protocols` нет.
- **Баллы** — только отчёт/пересчёт; сущности `НачислениеБаллов` в доменной модели нет.
- **Видео** — отдельная сущность (не поля на `Поединок`): обязательно связано с `Мероприятие` (`Мероприятие "1" -- "0..*" Видео`); опционально с `Поединок` (`Поединок "0..1" -- "0..*" Видео` — у видео 0..1 поединок, у поединка 0..* видео). `ДеньЦеликом` — только мероприятие (поединок null); `Поединок` — может ссылаться на поединок. Без `статусВидео` / статуса обработки в модели.
- **Название/подпись ситуации** — не отдельное хранимое поле: как в Google, это **конкатенация** (вычислимое) из `код` + `номер` (или принятого формата подписи из этих полей). В модели нет «дыры» названия.
- **Длительность раунда** — атрибут на `Поединок`: `длительностьРаундаМин : Integer` (как в расписании / `DuelMinutesLength`: ∈ {5, 4, 1}). Связано с `Поединок.тип`: экспресс — всегда 1; парный — всегда 5; классика — всегда 4 или 5 (не 1).
- **Сессия таймера** ≈ **события протокола**, не отдельная сущность `timer_sessions` как главный путь. Runtime (фаза, смена хода, пауза, протест, голоса уже на `Судья`, жеребьёвка, расчет ситуации, раскрытие ситуации…) пишется как `СобытиеПротокола`. Снимок UI/часов можно кэшировать; **источник истины хода боя** — события протокола (+ актуальные поля `Поединок` / `Судья`).

Кратко по операционному контуру (визуальный канон — `.drawio` / SVG):

- **Мероприятие** — ярлык, название, тип, даты, статус; арбитр — только связью с `Человек` (не атрибуты класса); без `краткиеИтоги` / `заметки`. Видимость на портале выводится из статуса (не отдельное поле). Статус: Запланировано, Подготовка, Проведено, Отменено
- **УчастиеВОрганизацииМероприятия**, **Наблюдатель** — списки к мероприятию (`idУчастника`; ФИО из `Человек`); у участия в организации — `роль : РольОрганизатора` (обязательна; несколько ролей = несколько записей)
- **РегистрацияНаМероприятие** — заявки; ФИО/контакты и опциональный `idУчастника`
- **Ситуация** — банк ситуаций на диаграмме; связь с поединком `Ситуация "0..1" -- "0..*" Поединок` (в режиме `случайный` может быть без выбранной до `расчетСитуации`)
- **Поединок** — `дата` проведения; `ТипПоединка`; `длительностьРаундаМин` (∈ {5, 4, 1}; экспресс=1, парный=5, классика ∈ {4, 5}); ситуация — связью (не `idСитуации`); `режимПодготовки` (обычный / скрытыйДоНачала / случайный); актуальный состав (`игрок1Id` / `секундантИлиВторойИгрок1Id` / `игрок2Id` / `секундантИлиВторойИгрок2Id`); без «кто начинал», без ФИО и без полей видео на классе
- **Видео** — `ссылка`, `дата` (день записи/дня мероприятия); опц. `название`, опц. `тип` (`ТипВидео`: ДеньЦеликом | Поединок); связи — см. выше
- **ЖурналИзмененияПоединка** — история смены полей состава и пр. (`момент`, `поле`, `староеЗначение`, `новоеЗначение`, опц. `авторId`)
- **Судья** — актуальный список у поединка; `голос` на судье; ФИО только через `Человек`
- **СобытиеПротокола** — лог у поединка (`Поединок *--` 0..*); runtime сессии таймера тоже сюда (не отдельная сущность сессии); отдельного `ПротоколПоединка` нет; класс `Раунд` не используем
- Победитель/счёт — вычисление по голосам (и при необходимости по протоколу), без отдельного класса

Маппинг в MySQL (ниже) — черновик; InnoDB, utf8mb4.

### Человек

| Атрибут | Тип | Описание |
|---------|-----|----------|
| id | Integer | ключ |
| ФИО | String | канон «Фамилия Имя» |
| email | String | |
| telegram | String | @username или id |
| активен | Boolean | |
| заметки | Text | notes |

**Кто ссылается на Человека** (на диаграмме — ассоциации; состав поединка — атрибутами `*Id` без линий к `Человек`, чтобы не зашумлять диаграмму; Судья — ассоциацией).

Кратности на диаграмме: роль (УчастиеВОрганизацииМероприятия / Наблюдатель / Судья) всегда указывает на человека — `Человек "1" -- "0..*" Роль`; регистрация может быть без карточки — `Человек "0..1" -- "0..*" РегистрацияНаМероприятие`; арбитр на мероприятии необязателен — `Человек "0..1" -- "0..*" Мероприятие : арбитр`; членство — `Человек "1" -- "0..*" ЧленствоВКруге`, `Круг "1" -- "0..*" ЧленствоВКруге`.

| РегистрацияНаМероприятие | `idУчастника` / `участникФИО` (+ контакты заявки) |
| Игроки и секундант/2-й игрок | `игрок1Id`, `секундантИлиВторойИгрок1Id`, `игрок2Id`, `секундантИлиВторойИгрок2Id` (актуальный состав; история — журнал) |
| Судья | `idУчастника` (ассоциация с `Человек`) |

### ЧленствоВКруге

Связь Человек — Круг; у записи ровно один человек и один круг. Человек может быть в нуле или многих кругах; в круге — много членов.

| Атрибут | Тип | Описание |
|---------|-----|----------|
| степеньВовлечения | String | роль/ступень в круге (не enum на диаграмме) |

Примеры значений `степеньВовлечения`:

- круг **Я-ИТ_ы**: `ЧС_A1`, `ЧС_B2`, …
- круг **ФУБ**: `Функционер ФУБ`, `Профессиональный судья`, `Профессиональный арбитр`, …

### Ситуация

Банк ситуаций — доменная сущность. Класс и связь — на [`05_схема_БД.drawio`](05_схема_БД.drawio) / [SVG](05_схема_БД.svg): `Ситуация "0..1" -- "0..*" Поединок`. Подпись ситуации — как в Google: **конкатенация** `код` + `номер` (вычислимое, не хранимое поле). Текст описания и ролей для UI вычисляется из JSON.

| Атрибут | Тип | Описание |
|---------|-----|----------|
| id | Integer | ключ |
| код | String | напр. `110` |
| номер | Integer | числовой номер из кода |
| тип | ТипПоединка | тот же enum, что у Поединок; см. перечисление ниже |
| описание | Json | структура описания ситуации |
| роли | Json | структура ролей |
| опубликована | Boolean | |

У поединка ситуация — ассоциацией (не атрибут `idСитуации`); уровень подготовки игроков — `режимПодготовки` на `Поединок` (вместо бывшего флага `скрытьНазваниеСитуации`). Кто сейчас в составе — `*Id` на `Поединок` + актуальный список `Судья`; прошлые значения — `ЖурналИзмененияПоединка`. Видео — отдельная сущность **Видео**, не поля на `Поединок`.

### Видео

Гибкая сущность для дня целиком и видео поединка. Класс и связи — на [`05_схема_БД.drawio`](05_схема_БД.drawio) / [SVG](05_схема_БД.svg): `Мероприятие "1" -- "0..*" Видео`, `Поединок "0..1" -- "0..*" Видео`.

| Атрибут | Тип | Описание |
|---------|-----|----------|
| id | Integer | ключ |
| ссылка | String | URL |
| дата | Date | день (дня мероприятия / дата видео поединка) |
| название | String | опционально; подпись |
| тип | ТипВидео | опционально: ДеньЦеликом \| Поединок |

Каждое видео обязательно принадлежит одному мероприятию; к поединку — опционально (0..1). `ДеньЦеликом` — только мероприятие (`поединок` null); `Поединок` может ссылаться на поединок. У мероприятия и у поединка — по 0..* видео. Статус обработки видео в модели **нет**.

Методички закрепа TG — **не в модели**: статичные ссылки на портале.

### Перечисления типов

| Перечисление | Значения |
|--------------|----------|
| ТипМероприятия | онлайн, купала, новогоднее, региональный, турнир |

| РежимПодготовкиИгроков | обычный, скрытыйДоНачала, случайный |
| РольОрганизатора | планированиеМероприятия, подготовкаУчастников, работаСНовичками, показывалЧасы, велЗапись, настраивалКомнатыZoom, экспертныйКомментарий, организацияПомещения, подготовкаМатериалов, подведениеИтогов, обновлениеДанных, обработкаВидео |
| КоллегияСудьи | нанимающиесяНаРаботу, отправляющиеНаПереговоры, доверяющиеСобственность, неизвестна |
| ИсточникИтога | таймер, бумага, google, вручную |

| ТипВидео | ДеньЦеликом, Поединок |

`РежимПодготовкиИгроков` (`режимПодготовки` на `Поединок`) — уровень/режим подготовки для игроков:

- **обычный** — ситуация и подпись известны заранее, обычная подготовка;
- **скрытыйДоНачала** — организаторы определяют ситуацию заранее, но игроки и другие участники о ней не знают (сюрприз). Раскрытие — к началу поединка / по правилам таймера (событие `раскрытиеСитуации`). Не путать со `случайный`. Покрывает бывший флаг `скрытьНазваниеСитуации`.
- **случайный** — ситуация заранее не выбрана, выбирается розыгрышем; фиксируется событием `расчетСитуации`.

Типы событий протокола, важные для «сессии» боя: `стартРаунда`, `конецРаунда`, `сменаХода`, `пауза`, `протест`, `голос`, `жеребьёвка`, `расчетСитуации`, `раскрытиеСитуации`, `выборРоли`, `завершение` (payload — по типу).

## 6. Сессия таймера ≈ события протокола

Отдельная сущность/`timer_sessions` **не** главный путь и не обязательный слой домена. Снимок UI/часов (phase, остатки таймеров) можно кэшировать (localStorage / опц. кэш-таблица позже) — это не источник истины.
