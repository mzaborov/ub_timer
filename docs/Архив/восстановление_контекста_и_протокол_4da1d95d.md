# Восстановление полного контекста онлайна и доработка протокола

В разделах 1–3 — **описание функционала и решений** (что делаем, как решаем). В разделе 4 — **реализация** (файлы, JS, порядок внедрения).

---

## Текущее состояние

- **localStorage**: сохраняется только расписание (имя файла) и список поединков с результатами. Состояние раунда (часы, текущий игрок, раунд, голоса судей) не сохраняется. Запись происходит при загрузке файла расписания и при подтверждении завершения поединка.
- **Восстановление**: по кнопке «Восстановить последний онлайн» восстанавливаются список поединков и имя файла, перерисовывается список поединков; главная форма с таймерами и форма судей не открываются, выбранный поединок не восстанавливается.
- **Протокол Excel**: один лист с колонками по поединкам; строки — игроки, победитель, судьи (фиксированно до 3 колонок длительностей раундов). Паузы/протесты и роли по раундам не выводятся; длительности только раундов 1–3, последний раунд может не попадать.
- **Завершение поединка**: после подтверждения модалка закрывается, данные пишутся в список поединков и в localStorage; переход к следующему поединку в списке не выполняется.

## 1. Расширение сохраняемого состояния и восстановление этапа

### 1.1 Что сохранять

Ввести «сессионное» состояние и писать его в то же хранилище (вместе с именем файла расписания и списком поединков):

- **Фаза**: простой | раунд | судьи (`idle` | `round` | `judges`).
- **При фазе «простой»** (поединок не идёт, форма судей не открыта): сохранять **текущий выбранный поединок** (индекс в списке), чтобы при восстановлении пользователь видел тот же поединок.
- **При фазе «раунд»** (идёт поединок):
  - выбранный поединок (индекс в списке);
  - номер текущего раунда;
  - остаток времени у игрока 1 и игрока 2 (сколько секунд на часах у каждого);
  - остаток времени на старте текущего сегмента у каждого игрока (для учёта длительностей);
  - длительности уже прошедших раундов (сколько длился раунд 1, раунд 2, …);
  - текущий активный игрок (1 или 2);
  - имена игроков (из полей ввода или из данных поединка);
  - флаг «поединок идёт», флаг «часы идут» (при восстановлении часы всегда останавливать);
  - длительность поединка (секунд), тип поединка (классика/экспресс), число судей — для корректного отображения.
- **При фазе «судьи»** (открыта форма судей после «Завершить поединок»):
  - всё то же, что для фазы «раунд», но раунд уже завершён (часы остановлены, последний сегмент уже в длительностях прошедших раундов);
  - список судей: голос каждого (1/2/0), видимость (и при необходимости подпись, колледж для отрисовки);
  - активный судья (индекс или идентификатор).

Сохранение вызывать:

- при выборе поединка из списка (фаза `idle`, сохраняется текущий выбранный поединок);
- при старте поединка (фаза → `round`);
- при смене игрока (обновить раунд, время, длительности уже прошедших раундов);
- при нажатии «Завершить поединок» перед открытием модалки судей: записать фазу `judges`, текущие длительности раундов (включая последний сегмент), остаток времени и т.д.;
- при изменении голоса судьи и при смене активного судьи (обновить голоса и активного судью);
- **в тике таймера** (в том же интервале, что обновляет часы): при каждом тике во время раунда перезаписывать в localStorage текущие значения времени обоих игроков и связанное состояние раунда — при крахе браузера не теряются последние секунды (отдельный интервал не нужен).

При загрузке нового файла расписания — перезаписывать состояние полностью: новый список поединков, имя файла расписания, фаза «простой», выбранный поединок по желанию (например, первый). Старое сохранённое состояние не нужно.

### 1.2 Восстановление этапа при «Восстановить последний онлайн»

Логика восстановления (общая для источника: localStorage или загруженный файл):

1. Восстановить имя файла расписания, список поединков, отобразить список в UI.
2. Восстановить выбранный поединок: если в данных есть текущий индекс поединка (в т.ч. при фазе `idle`), выделить и отобразить тот же поединок (ситуация, имена, роли и т.д.).
3. Если фазы нет или фаза `idle` — на этом закончить.
4. **Если фаза `round`** (идёт раунд): восстановить номер раунда, остатки времени обоих игроков, длительности уже прошедших раундов, текущего игрока, тип поединка и число судей; выставить флаги «поединок идёт», «часы остановлены»; обновить экран (подписи игроков, донаты, цифры таймеров, блок «Раунд №N», активный игрок, кнопка «Завершить поединок»); модалку судей не открывать. Важно не сбрасывать восстановленное время при инициализации таймеров.
5. **Если фаза `judges`** (открыта форма судей): то же восстановление состояния раунда; восстановить голоса судей и активного судью; отобразить форму судей с уже проставленными голосами и подсветкой активного судьи; открыть модальное окно формы судей.

### 1.3 Баннер восстановления: кнопки «Сохранить/загрузить статус онлайна в файл»

На баннере восстановления добавить две кнопки:

- **«Сохранить статус онлайна»** — скачать один файл .xlsx с листами «Протокол», «Раунды» и «Состояние сессии» (см. п. 2).
- **«Загрузить статус онлайна»** — выбор файла .xlsx; разбор листов «Протокол» и «Раунды» в данные поединков; при наличии листа «Состояние сессии» — восстановление этапа по той же логике, что в п. 1.2; запись в localStorage; при успехе скрыть баннер.

## 2. Вид протокола и сохранение/загрузка статуса в одном Excel

### 2.0 Как будет выглядеть протокол

Один лист — один тип данных. Первый столбец (или первые столбцы) — подписи, далее по столбцам — поединки (Поединок 1, Поединок 2, …). **Данные по раундам** вынесены в отдельную вкладку «Раунды».

- **Лист «Протокол»** — только общие данные поединка. Без строк по раундам. Структура:


| Строка (подпись) | Содержимое по столбцам-поединкам |
| ---------------- | -------------------------------- |
| Игрок 1          | Имя игрока 1                     |
| Игрок 2          | Имя игрока 2                     |
| Победитель       | Имя победителя                   |
| Судья 1          | Голос (1 или 2)                  |
| Судья 2          | Голос (1 или 2)                  |
| …                | …                                |
| Судья N          | Голос (1 или 2)                  |


Судьи — **N отдельных строк** (по одной на каждого судью). N = максимальное число судей по всем поединкам (5, 7 или 9). У поединков с меньшим числом судей лишние строки пустые.

- **Лист «Раунды»** — таблица: каждая **строка = один раунд одного поединка**. Столбцы:


| Поединок | Раунд | Длительность | Игрок 1 Роль | Игрок 2 Роль | Время паузы | Протесты   |
| -------- | ----- | ------------ | ------------ | ------------ | ----------- | ---------- |
| 1        | 1     | 2:30         | …            | …            | 1:45        |            |
| 1        | 2     | 3:00         | …            | …            |             | 0:50, 1:20 |
| 2        | 1     | …            | …            | …            |             |            |


Роли — только для классики; для экспресса столбцы ролей пустые. В колонке «Протесты» — список времён через запятую (протестов может быть сколько угодно). При отсутствии пауз/протестов — ячейки пустые.

**Текущий статус для восстановления** — в **отдельной вкладке «Состояние сессии»** (третья вкладка). В «Протокол» и «Раунды» — только результаты; текущий статус экрана хранится отдельно, чтобы при «Загрузить статус онлайна» восстановить тот же этап. Структура вкладки — таблица «ключ — значение» (например, столбец A: ключ, столбец B: значение):


| Поле                               | Описание                                          | Пример            | Когда заполняется       |
| ---------------------------------- | ------------------------------------------------- | ----------------- | ----------------------- |
| Имя файла расписания               | имя загруженного файла расписания                 | Онлайн я-ИТ-ы №25 | всегда                  |
| Фаза                               | текущий этап экрана                               | раунд             | всегда                  |
| Выбранный поединок                 | индекс поединка в списке (0, 1, 2, …)             | 2                 | всегда                  |
| Остаток времени игрок 1            | сколько секунд осталось на табло у игрока 1       | 185               | при «раунд» или «судьи» |
| Остаток времени игрок 2            | сколько секунд осталось на табло у игрока 2       | 240               | при «раунд» или «судьи» |
| Номер текущего раунда              | какой по счёту раунд идёт                         | 3                 | при «раунд» или «судьи» |
| Длительности уже прошедших раундов | сколько длился раунд 1, раунд 2, … (сек или M:SS) | 150, 180          | при «раунд» или «судьи» |
| Текущий активный игрок             | кто сейчас ходит: 1 или 2                         | 1                 | при «раунд» или «судьи» |
| Длительность поединка              | лимит времени на игрока (секунд)                  | 300               | при «раунд» или «судьи» |
| Тип поединка                       | классика или экспресс                             | классика          | при «раунд» или «судьи» |
| Число судей                        | количество судей (5, 7 или 9)                     | 9                 | при «раунд» или «судьи» |
| Голоса судей                       | голос каждого судьи: 0 / 1 / 2                    | 1,2,1,0,2,1,2,1,2 | при фазе «судьи»        |
| Активный судья                     | индекс судьи, который сейчас голосует             | 3                 | при фазе «судьи»        |
| lastCompletedDuelIndex            | индекс только что завершённого поединка (для кнопки «Вернуть голосование») | 0                 | при фазе «idle», если был завершён поединок |


Итого в файле **три вкладки**: 1) **Протокол** — общие результаты; 2) **Раунды** — детали по раундам; 3) **Состояние сессии** — текущий статус для восстановления экрана. При загрузке статуса читаем все три (если третьей нет — восстанавливаем только список поединков и имя файла, фаза = простой).

### Сохранение/загрузка статуса онлайна — через тот же Excel (без отдельного JSON)

Использовать **один файл .xlsx** вместо отдельного JSON:

- **«Сохранить статус онлайна»**: скачивать Excel с **тремя вкладками**: «Протокол», «Раунды», «Состояние сессии» (текущий статус — см. таблицу выше, включая **lastCompletedDuelIndex** при фазе idle после завершения поединка). Данные берутся из списка поединков и текущего раунда, если поединок не завершён.
- **«Загрузить статус онлайна»**: пользователь выбирает .xlsx. Читаем «Протокол» → восстанавливаем список поединков (игроки, победитель, судьи). Читаем «Раунды» → заполняем по поединкам длительности раундов, роли, паузы и протесты. Читаем «Состояние сессии» → восстанавливаем этап (фаза, выбранный поединок, часы, судьи, **lastCompletedDuelIndex** при фазе idle) по логике из п. 1.2; при phase idle и наличии lastCompletedDuelIndex показывается кнопка «Вернуть голосование». Если вкладки «Состояние сессии» нет — восстанавливаем только список поединков и имя файла, фаза = простой, выбран первый поединок.

Так и официальный протокол, и резервная копия/перенос — в одном формате Excel; отдельный JSON не нужен.

## 3. Баги и расширение протокола

### 3.1 Время последнего раунда в протоколе

- **Решение:** при завершении поединка последний сегмент (текущий раунд до нажатия «Завершить поединок») должен всегда попадать в сохраняемые длительности раундов. Проверить сценарии: завершение по кнопке, закрытие модалки — данные не теряются.
- **Решение:** протокол должен поддерживать **произвольное число раундов**, а не только три. В листе «Раунды» каждая строка — раунд поединка, колонка «Длительность»; число строк по раундам — по факту у каждого поединка.

### 3.2 Секунда пауз и протестов

- При нажатии «Пауза» (вход в паузу) и при нажатии «Протест» записывать событие: раунд, игрок, остаток игрового времени у активного игрока в этот момент. Хранить массив событий по поединку (тип: пауза/протест, раунд, игрок, время). **Протестов в раунде может быть сколько угодно** — структура данных должна хранить список времён протестов по раундам (например, массив объектов по раундам с полем protests: [время1, время2, …]). В листе «Раунды» — одна колонка «Протесты» с перечислением времён через запятую для данного раунда.

### 3.3 Роли по раундам

- **Только для классики.** При смене игрока перед очисткой полей ролей сохранять для текущего раунда: кто какую роль играл. Хранить массив по раундам (роль игрока 1, роль игрока 2); при завершении поединка записывать в данные поединка. В листе «Раунды» — колонки «Игрок 1 Роль», «Игрок 2 Роль» по раундам.
- **Для экспресса** роли по раундам не сохранять и не выводить: там только кто игрок 1 и кто игрок 2 (уже в листе «Протокол»).

### 3.4 Переход к следующему поединку после завершения

- **Решение:** после подтверждения завершения поединка (сохранение в список поединков и в localStorage, закрытие модалки) — если поединок не последний в списке, переключить выбор на следующий поединок; таймеры и раунды сбросить под новый поединок. Если поединок последний — ничего не менять.

## 4. Реализация

Здесь — уровень кода, файлов и порядка внедрения. В разделах 1–3 выше — только функционал и решения «что делать» и «как решать». Ниже — скелет; **при реализации будем расписывать подробнее**: конкретные имена функций, номера строк или места вставки, фрагменты кода, проверки.

**Файлы**

- **js/timer-code.js** — состояние (переменные раунда, таймеров, судей), сохранение/восстановление в localStorage, построение и скачивание протокола, обработчики раунда (старт/стоп поединка, смена игрока, пауза/протест), форма судей, выбор поединка. Ключевые функции: сохранение состояния в localStorage с расширенным payload (фаза, currentDuel, время, roundDurations, refereeList и т.д.); восстановление из localStorage или из загруженного Excel; формирование Excel с листами «Протокол», «Раунды», «Состояние сессии» (XLSX); разбор загруженного Excel.
- **index.html** — баннер восстановления, кнопки «Сохранить/загрузить статус онлайна», скрытый input для выбора .xlsx; модалка формы судей, поля имён и раунда.

**Порядок внедрения (рекомендуемый)**

1. Протокол: листы «Протокол» и «Раунды», произвольное число раундов, паузы/протесты (протестов сколько угодно — одна колонка «Протесты» со списком времён), роли по раундам (классика). Совместимость: старые протоколы без новых полей должны открываться и скачиваться без ошибок.
2. Сохранение сессионного состояния: расширить payload (фаза, currentDuel, время, раунды, судьи), вызывать сохранение при выборе поединка, start_duel, stop_duel, switchPlayer, голос/смена судьи, в тике таймера во время раунда.
3. Восстановление этапа: общая функция применения загруженных данных; ветки фазы round и judges; открытие модалки судей при judges; не сбрасывать время при восстановлении.
4. Кнопки «Сохранить/загрузить статус онлайна»: формирование и скачивание .xlsx (три листа); разбор .xlsx при загрузке, вызов общей логики восстановления.
5. Переход к следующему поединку после подтверждения завершения.
6. Проверка: восстановление при раунде и при форме судей; протокол с N раундами, паузами, протестами (в т.ч. несколько), ролями; переход на следующий поединок.

## 5. Что сделано (детально)

Ниже — перечень реализованных изменений после выполнения плана и последующих доработок.

### 5.1 Сохранение и восстановление состояния

- **buildSessionStatePayload()** — формирует объект состояния: `phase`, `currentDuel`, `time0`/`time1`, `roundStartRemaining0`/`1`, `roundDurations`, `current_round`, `current_player`, `game_time`, `duelType`, `refereeQty`, `player1Name`/`player2Name`, `roundRoles`, `pauseProtestEvents`, для фазы judges — `refereeVotes`, `activeReferee`; для раунда/judges — `currentRoundRole1`/`currentRoundRole2` из текущих выбранных ролей в селектах.
- **saveProtocolStateToLocalStorage()** — сохраняет в localStorage под ключом `PROTOCOL_STORAGE_KEY` объект с `duelsList`, `scheduleFileName` и payload из `buildSessionStatePayload()`. Вызывается при выборе поединка, старте/остановке поединка, смене игрока, выборе роли, в тике таймера во время раунда, при голосе/смене судьи.
- **restoreProtocolStateFromLocalStorage()** — читает localStorage, восстанавливает список поединков и имя файла, перерисовывает список, вызывает `duelChoosed(currentDuel)` для выбранного поединка, при phase idle подставляет роли из `currentRoundRole1`/`2`, затем **applyRestoredSessionState(data)** для восстановления этапа (round/judges). Флаг **isRestoringProtocol** блокирует перезапись localStorage в `duelChoosed` во время восстановления; в конце вызывается **saveProtocolStateToLocalStorage()**.
- **applyRestoredSessionState(data)** — при phase `round` или `judges` восстанавливает время, раунд, игрока, длительности, роли, паузы/протесты; для classic — подставляет роли текущего раунда из `roundRoles` или `currentRoundRole1`/`2` в селекты; при phase `judges` вызывает **initRefereeStructure(refereeQty)** и выставляет радиокнопку 9/7/5, восстанавливает **refereeVotes** и **activeReferee**, открывает модалку формы судей.

### 5.2 Роли и длительности раундов

- **Роли 1-го раунда при старте:** в **start_duel()** после обнуления `roundRoles` для типа «классика» считываются текущие роли из селектов; в массив пушится запись только если выбрана хотя бы одна роль и текст не плейсхолдер «Выберите Роль...».
- **Длительность при первом «Переход хода»:** в **changePlayer()** перед сменой игрока сохраняется **previousPlayer = current_player**; длительность сегмента и обновление **roundStartRemaining** считаются по **previousPlayer** (игрок, чей ход завершился), а не по уже сменившемуся `current_player`, чтобы в **roundDurations** попадала корректная длительность.
- **Обновление ролей в текущем раунде:** в **roleChoosed()** при phase `round` и классике обновляется **roundRoles[current_round - 1]** (создаётся при необходимости); новые строки в `roundRoles` не добавляются — только правка текущего раунда.
- **Роли при смене хода:** в **changePlayer()** роли завершённого раунда читаются из селектов до их сброса и пушатся в **roundRoles**; затем селекты очищаются.

### 5.3 Протокол и экспорт в Excel

- **Экспорт «Сохранить статус онлайна»:** формируется .xlsx с тремя листами. **Протокол** — игроки, победитель, судьи (голоса 1/2); для текущего поединка при phase **judges** голоса берутся из **payloadExport.refereeVotes**, чтобы в файле были актуальные результаты голосования. **Раунды** — строки по раундам с длительностью, ролями, паузой, протестами; для текущего поединка при phase **round** добавляется строка для **текущего** раунда (число строк = max(durations.length, roles.length, current_round)); при phase **judges** строка текущего раунда не добавляется (нет лишнего раунда с пустыми данными). Роли текущего раунда при экспорте подставляются из **currentRoundRole1**/`2` при необходимости. **Состояние сессии** — таблица «ключ — значение» для восстановления этапа.
- **Импорт «Загрузить статус онлайна»:** доступен только после загрузки файла расписания. Пункт меню «Загрузить статус онлайна» по умолчанию неактивен; после загрузки расписания — активен. При загрузке .xlsx список поединков **не пересобирается** из листа «Протокол»: обновляются только поля существующих поединков (игроки, победитель, судьи) по индексу; лист «Раунды» дополняет **RoundDurations**, **RoundRoles**, **PauseProtestEvents**; лист «Состояние сессии» восстанавливает этап через **applyRestoredSessionState**. Добавлены проверки на undefined при разборе листов (firstRow, roundsAoa, sessionAoa).

### 5.4 Завершение поединка и переход к следующему

- **finishDuelAndClose()** — сохраняет победителя и голоса судей в **duelsList[currentDuel]**, устанавливает **sessionPhase = "idle"**, **duel_is_active = false**, возвращает кнопку «Начать поединок» и стиль, вызывает **enable_disable_duel_options_conrols("hidden", false)** (разблокируются кнопки «Выберите файл» и «Выберите поединок»), **initTimers()**, скрывает кнопку «Голосование судей», закрывает модалку; при наличии следующего поединка вызывается **duelChoosed(currentDuel + 1)**.

### 5.5 Форма голосования судей: кнопка «Вернуть голосование»

- На главной под кнопкой «Начать поединок» добавлена кнопка **«Вернуть голосование»**. Показывается в фазе **idle**, если только что был завершён поединок (в **finishDuelAndClose** сохраняется **lastCompletedDuelIndex = currentDuel**, затем при наличии следующего поединка вызывается **duelChoosed(currentDuel + 1)**; кнопка показывается после этого). Скрывается при **start_duel()** (начало следующего поединка).
- По нажатию открывается форма судей **для предыдущего поединка** (lastCompletedDuelIndex): вызов **duelChoosed(lastCompletedDuelIndex)**, **initRefereeStructure** и подстановка **JudgeVotes** из duelsList, фаза → `judges`, показ модалки.
- **lastCompletedDuelIndex** сохраняется в **localStorage** (в **buildSessionStatePayload()** при значении не null) и в листе **«Состояние сессии»** при экспорте (ключ `lastCompletedDuelIndex`). При восстановлении из localStorage и при загрузке файла статуса: если фаза `idle` и в данных есть валидный **lastCompletedDuelIndex**, переменная восстанавливается и кнопка «Вернуть голосование» показывается.
- Обработчик **hidden.bs.modal** на **finishDuelModal**: при закрытии модалки показывается кнопка, если phase `judges` или (phase `idle` и lastCompletedDuelIndex задан).

### 5.6 Прочие исправления

- **Количество судей при восстановлении:** в **applyRestoredSessionState** при phase `judges` вызывается **initRefereeStructure(refereeQty)** (а не -1) и выставляется радиокнопка **refereeQty + "ref"**; значение **refereeQty** из данных применяется только если 9, 7 или 5.
- **roleChoosed:** защита от undefined при обращении к **duelsList[currentDuel].SituationRoles[role]** и к селекту второго игрока; при отсутствии данных цели ролей и блокировки опций не ломают страницу.
- **duelChoosed:** при отсутствии **DuelMinutesLength** или недопустимом значении не вызывается **getElementById(…+"min").checked**; для типа поединка перед установкой **checked** проверяется существование элемента. При импорте статуса поединкам без длительности задаётся **DuelMinutesLength = 5**.
- Кнопка **«Загрузить статус онлайна»** перенесена из баннера в выпадающее меню под кнопкой «Выберите файл»; по умолчанию отображается выпадающая кнопка файла (не простая), чтобы пункт «Загрузить статус онлайна» был доступен после загрузки расписания.
