# Happy-path часов в режиме БД — ub-timer

**Дата прогона:** 2026-10-15
**Среда:** прод `https://timer.zaborov.ru/`, версия выкладки **v121**
**Браузер:** Yandex Browser 26.8 (Chrome 150), управление — Playwright MCP
**Тестовое мероприятие:** `id 67` «ТЕСТ БД 2026-10-15» (копия онлайна id 31; статус «Подготовка», `starts_on` = 2026-10-15)
**Состав теста:** 8 поединков — классика (№1, №2, №4–№7), экспресс (№3, 5 судей), парный (№8); 38 человек (новички, опытные, орг, «судья ФУБ», один неактивный); 59 судей, 4 организатора.

## Happy path — пошагово

### 1. Меню «Загрузить расписание» → «из базы»

В подменю загрузки расписания рядом с «из Google» и «из файла» появился пункт **«из базы»** — канон из общей БД портала.

![01](db-happy-path-2026-10-15/01-menu-iz-bazy.png)

### 2. Выбор мероприятия из базы

Открывается модалка со списком мероприятий. В прод-режиме (`timer.zaborov.ru`) показываются сегодняшние; здесь — тестовое «ТЕСТ БД 2026-10-15».

![02](db-happy-path-2026-10-15/02-picker-event.png)

### 3. Состав из БД загружен

Часы собрали `duelsList` из базы: 8 поединков, ФИО из справочника людей (локальных записей нет), ярлыки опыта считает сервер.

![03](db-happy-path-2026-10-15/03-schedule-loaded.png)

### 4. Список поединков — ситуации из БД

В выпадающем списке поединков — реальные ситуации из общей БД (№12 «Увидеть лес за деревьями», №69 «Переход на новую бухгалтерскую систему» и т.д.).

![04](db-happy-path-2026-10-15/04-duel-list.png)

### 5. Выбран поединок №1 — ситуация и участники из БД

При выборе поединка на часы подставляются ситуация, игроки и секунданты из БД; пишется событие `раскрытиеСитуации`.

![05](db-happy-path-2026-10-15/05-duel1-selected.png)

### 6. «Участники и судьи» — ярлыки опыта

Справочник людей с вычисляемыми ярлыками: **опытный / новичок / орг / судья ФУБ**; ручные радио опыта в режиме БД скрыты (их заменили бейджи).

![06](db-happy-path-2026-10-15/06-participants-labels.png)

### 7. Раскладка судей из `duel_judges`

Таблица «Расписание» — судьи по коллегиям (нанимающиеся / отправляющие / доверяющие) из базы; пустые слоты формы в БД не пишутся.

![07](db-happy-path-2026-10-15/07-judges-layout.png)

### 8. Классика (№1): начало поединка, раунд 1

Оператор нажал «Начать поединок» — пишутся `началоПоединка` и `стартРаунда`, идёт отсчёт.

![08](db-happy-path-2026-10-15/08-start-duel-round1.png)

### 9. Жеребьёвка и выбор ролей

Кубик определил начинающего (`жеребьёвка`), выбраны управленческие роли обоих игроков (`выборРоли`).

![09](db-happy-path-2026-10-15/09-dice-roles.png)

### 10. Смена хода → раунд 2

«Переход хода» — фиксируются `сменаХода` и новый `стартРаунда`.

![10](db-happy-path-2026-10-15/10-change-player-round2.png)

### 11. Пауза

Вход в паузу и выход из неё — две записи события `пауза` (round + player).

![11](db-happy-path-2026-10-15/11-pause.png)

### 12. Протест

Протест секунданта — событие `протест` (вход и снятие).

![12](db-happy-path-2026-10-15/12-protest.png)

### 13. Корректировка часов

Двойной клик по цифрам → ввод `3:30` → событие `корректировкаВремени` с прежним и новым значением.

![13](db-happy-path-2026-10-15/13-clock-correction.png)

### 14. Завершение поединка

«Завершить поединок» — событие `завершение` и форма судей с текущим составом коллегий.

![14](db-happy-path-2026-10-15/14-finish-judges-form.png)

### 15. Голоса судей

На каждое изменение голоса — событие `голос` и upsert значения в `duel_judges.vote`.

![15](db-happy-path-2026-10-15/15-judge-votes.png)

### 16. Согласие судьи (зелёные ячейки)

Подтверждение ячейки судьи — событие `согласиеСудьи` и флаг `duel_judges.agreed` (зелёная подсветка читается из базы).

![16](db-happy-path-2026-10-15/16-judges-agreed-green.png)

### 17. Решение судей

Финальное подтверждение — событие `решениеСудей`; победитель определён по большинству голосов.

![17](db-happy-path-2026-10-15/17-decision-winner.png)

### 18. Экспресс (№3): 5 судейских слотов

Экспресс — вместимость 5 судейских мест, коллегия только «Отправляющие на переговоры», без секундантов.

![18](db-happy-path-2026-10-15/18-express-5-judges.png)

### 19. Парный (№8)

Парный поединок: игроки — пары, подписи формируются как «Игрок + Секундант».

![19](db-happy-path-2026-10-15/19-pair-duel8.png)

### 20. Правка состава → журнал изменений

Замена судьи в слоте (слот `j0`) — обновление `duels`/`duel_judges` и строка в `duel_change_log`.

![20](db-happy-path-2026-10-15/20-composition-edit.png)

### 21. F5 — баннер восстановления

После перезагрузки сверху появляется предложение восстановить последний онлайн.

![21](db-happy-path-2026-10-15/21-restore-banner.png)

### 22. Восстановлено из БД

По «Да» канон берётся из БД (8 поединков, 38 человек), источник расписания и id мероприятия восстанавливаются из LS-снимка; `situation_id` цел.

![22](db-happy-path-2026-10-15/22-restored-from-db.png)

## Итог в БД (проверка SQL)

Один чистый прогон по мероприятию `id 67`:

- `duels` = 8; `duel_judges` — согласий (`agreed=1`) = 3, голоса записаны.
- `protocol_events` = **69**, разбивка:
  `голос` 23, `раскрытиеСитуации` 8, `стартРаунда` 7, `выборРоли` 6, `началоПоединка` 4, `завершение` 4, `решениеСудей` 4, `сменаХода` 3, `согласиеСудьи` 3, `жеребьёвка` 2, `пауза` 2, `протест` 2, `корректировкаВремени` 1.
- `duel_change_log` = 1.
- По поединкам: №1 (классика) 26 событий, №2 (классика) 20, №3 (экспресс) 12, №4 2, №8 (парный) 9.

Все типы соответствуют справочнику `ТипСобытияПротокола`: пауза пишется двумя событиями (вход/выход), `началоПоединка` и `стартРаунда` — раздельно, `раскрытиеСитуации` — при выборе поединка.

## Замечания и ограничения

- У поединка №8 в базе не было судей (`duel_judges=0`), поэтому голоса по нему не материализовались — ожидаемо для поединка без назначенных судей.
- **Не проверялись в этом прогоне:** офлайн-очередь при недоступной БД (9.14), отдельный таймер судей на 1 минуту (9.8), перестановка поединков кнопками (9.11, UI в часах пока нет), просмотр лога оргом на втором устройстве (9.13, задача 11).
- Тестовые данные удаляются по команде: `python scripts/make_test_event.py drop --id 67`.
