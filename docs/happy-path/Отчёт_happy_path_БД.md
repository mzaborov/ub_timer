# Happy-path: часы в режиме БД (timer-on-portal-db, шаг 3)

**Дата прогона:** 2026-10-15
**Среда:** прод `https://timer.zaborov.ru/`, версия выкладки **v121**
**Браузер:** Yandex Browser 26.8 (Chrome 150), управление — Playwright MCP (headless, свой инстанс без прокси)
**Тестовое мероприятие:** `id 66` «ТЕСТ БД 2026-10-15» (копия онлайна id 31; статус «Подготовка», `starts_on` = 2026-10-15, 8 поединков: классика×6 + парный + экспресс)
**Секреты:** не использовались в отчёте; SQL — только через серверный PHP с токеном (`scripts/make_test_event.py`).

## Что проверяли

Полный цикл боевого дня в режиме «расписание из базы»: загрузка канона из БД, проход классики/парного/экспресса, голоса и согласие судей, решение судей, правка состава, корректировка часов, восстановление после F5, запись всех событий и состава в общую БД портала.

## Ограничения и замечания

- **Правка часов** (`корректировкаВремени`) проверена; при повторном выборе поединка событие `раскрытиеСитуации` пишется снова (по одному на выбор) — это соответствует домену «поединок открыли/выбрали».
- **Офлайн-очередь** (9.14) не прогонялась эмуляцией отключения сети — очередь и ретраи реализованы, но сценарий обрыва оставлен на отдельную проверку.
- **Автозаполнение судей** (`runJudgesAutofill`) в этом прогоне не запускалось целиком (чтобы не затирать уже проведённые поединки); проверена точечная правка слота + журнал изменений.
- **Не проверялись в этом прогоне:** отдельный таймер судей на 1 минуту (9.8), перестановка поединков кнопками (9.11 — UI в часах ещё нет, задача 10.2), просмотр лога оргом на втором устройстве (9.13 — задача 11).
- Тестовые данные (`event_id 66`) удаляются по команде: `python scripts/make_test_event.py drop --id 66`.

## Вывод

Happy-path в режиме БД пройден без ошибок в консоли: канон (состав, ситуация, судьи, голоса, согласие) и полный лог событий пишутся в общую БД портала; источник расписания переживает перезагрузку; Google-режим и работа без БД не затронуты.
